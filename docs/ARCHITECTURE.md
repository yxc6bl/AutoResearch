# 架构论证：论文产出是一个系统问题，不是一个模型问题

> 这份文档回答一个问题：为什么本工程的价值不能归因于「换了个更强的模型」，
> 而必须归因于**契约、闸门、证据链**这三层系统设计。文中每个论断都指向仓库里的
> 真实产物或可复跑的命令；没有产物的设想一律写进「边界」，不作为论据。
>
> 参考对象是 nanoMuse（浙江大学 APRIL 实验室，2026-10）的核心判断——
> 「个人智能体是一个软件问题，不是一个模型问题；它跑在哪里、由谁运行、
> 在谁的注视下运行，这些不是部署细节，这些就是产品本身」。
> 本文把这套论证搬到「自动生成可交付论文」这个场景上，并给出本工程自己的答案。

---

## 零、结论先行

1. **同一个模型，可以产出不可交付的稿子，也可以产出 98.3 分的稿子；两次之间模型没换，
   改的全是系统。**（第 1 节，四轮 `hard_fail → hard_pass`）
2. **加权评分不能决定交付。** 有一份稿子规则评分 99.5 分、等级「优秀」，
   评审官同时给出 5 条事实矛盾，闸门判不可交付。（第 1.3 节）
3. **系统的核心能力不是「生成」，是「拒绝」与「说清楚为什么拒绝」。**
   四道 P0 闸门、回滚机制、人工放行留痕，构成了一套可以被答辩追问的系统，
   而不是一个抽奖式的生成器。（第 3、4 节）

## 一、一个可复现的对照实验：模型不变，系统变

### 1.1 实验设置

补关联规则（Apriori）后端后，用同一个题目、同一份数据、同一个模型
（`deepseek-v4-pro`，由 `WRITE_STATUS.json` 落盘记录）连跑四轮。
每轮只改系统层，不改模型、不改题目、不改数据。

| 轮次 | 模型 | 系统层改动 | 评审官结论 |
|---|---|---|---|
| 1 | deepseek-v4-pro | 模板沿用监督学习叙事（多种子方差、配对显著性检验） | `hard_fail`：lift 被四舍五入、正文称「划分训练集/测试集」、出现「第 None 轮」 |
| 2 | 同上 | 事实清单与正文统一 4 位小数；第 4 节改交易级说明；`_ground_truth` 补规则数值 | `hard_fail`：表 1 仍把 0.2047 写成 0.205；创新点称「提出框架」（事实是「采用」） |
| 3 | 同上 | `metrics.setting` 改 4 位；创新点改「采用」；重建实验产物 | `hard_fail`：第 6 章标题与正文出现「假设检验」（事实是「不做显著性检验」）；正文自算边际概率 0.2285/0.3300（事实清单外数字） |
| 4 | 同上 | 新增 `_deep_cn()` 把第 6 章改为「深入分析」；事实包加「禁止反推数字」硬约束 | **`hard_pass`，98.3 分，幻觉 0 条，16009 汉字，可交付** |

### 1.2 这个对照说明了什么

四轮里模型一次都没换，**变的全是「系统允许模型说什么」**：

- 事实清单给不给规则的三项指标（`_fact_pack` / `_ground_truth`）；
- 模板要不要按任务类型分支（`_deep_cn`、5.4 节、8.0 创新点）；
- 产物精度是不是和正文同源（`metrics.setting` 的 4 位小数）。

第一轮的问题不是「模型不会写论文」，而是**模板在说谎**：它把一套监督学习的叙事
（随机种子、训练/测试划分、显著性检验）套在一个确定性算法上。模型照着模板写，
写出来的每一句都「符合模板」，但每一句都不是这次实验的事实。
G04 把这些句子判成编造，判得对。

反过来，如果只把模型换成更强的，模板里的错误叙事仍然会被更流畅地写出来——
**模型越强，错误叙事越有说服力**，这是最危险的情况。所以约束必须放在系统层，
不能寄希望于模型自觉。

### 1.3 反向证据：分数高 ≠ 能交付

`out_gate_real`（乳腺癌分类，2026-11-05 全链路）：

| 指标 | 数值 |
|---|---|
| 规则评分门 `overall` | **99.5（优秀）** |
| LLM 评审官 | 74 分，`verdict=revise` |
| 评审官指出的幻觉 | **5 条**（McNemar 检验写成配对 t 检验、数据无缺失却写「中位数插补」、随机种子编号不一致、臆测 p 值、事实清单外的特征重要性表） |
| 闸门裁决 | **不可交付**（G04 未通过） |

如果交付只看加权总分，这份稿子会被当成「优秀」交出去。系统的价值恰恰在于：
**P0 硬门独立于加权分，只认事实。**

规则分与评审官分之间存在系统性落差（98~99.5 vs 74~78），这不是 bug，是两种测量的差别：
规则分测「结构完不完整」，评审官测「说得对不对」。把两者压成一个数，
就等于把「完整性」和「真实性」混为一谈。

## 二、分析框架：五问三层

借 nanoMuse 的「五问三层」，改成论文生产场景的版本。

### 2.1 五问

| 问题 | 本工程的答案 | 落点 |
|---|---|---|
| 谁在写？ | 一个可替换的模型，只负责把事实清单写成散文 | `paper/generate_paper.py` 的 `_fact_pack` → LLM 章节 |
| 在哪算？ | 本地确定性引擎，不联网、不调模型 | `engine/analysis_engine.py` |
| 证据存哪？ | 文件契约：JSON / Markdown / JSONL，可手改、可 diff、可重算 | `<out_dir>/` 下的产物 |
| 谁放行？ | 四道 P0 闸门；人工放行必须留名、留理由、保留原始状态 | `engine/gates.py`、`07_gate_approvals.json` |
| 模型坏了怎么办？ | 降级为模板稿并标「不可交付」；评审官缺席记 `unknown` 而不是 `pass` | `DELIVERY_STATUS.json`、G03/G04 |

### 2.2 三层

```
裁决层   gates.py / mark_delivery / 人工放行
         只回答「能不能交」，不改任何阶段行为
────────────────────────────────────────────────────
执行层   auto_research.py（编排） + agents/ 下的薄壳代理
         每个 stage 可单独重跑：step --name write|eval|...
────────────────────────────────────────────────────
契约层   ANALYSIS_JSON / DELIVERY_STATUS / WRITE_STATUS /
         07_eval_verdict / 00_trace / feedback.jsonl
         所有模块只通过这些文件交接，不靠内存对象
```

三层的关键约束是**单向依赖**：裁决层只读产物，执行层只写产物，契约层不知道谁在读它。
所以任何一层都可以被替换（换模型、换编排、换评分规则）而不动另外两层。

## 三、十个设计决策：选了什么、否了什么、代价是什么

每条决策都写成同一格式：**问题 → 选择 → 被否掉的替代方案 → 代价 → 证据**。
答辩时被问「为什么这么设计」，答案就在「被否掉的替代方案」这一栏。

### D1 文件契约，而不是内存消息

- **问题**：六个阶段如何交接状态？
- **选择**：每个阶段落一个 JSON/MD 文件，下一阶段只读文件。
- **否掉的替代**：agent 之间直接函数调用 / 消息队列。否掉的理由是断点续跑：
  文献抓 6 分钟、写作 19 分钟，中途挂掉必须能从任意阶段恢复。
  `step --name write|eval|experiment` 能单独跑，就是文件契约的直接收益。
- **代价**：字段契约要维护（`ANALYSIS_JSON` 五个必需字段），字段缺了正文就写不出数字。
- **证据**：`docs/BACKENDS.md` 的「四接线点」全部围绕文件契约定义；
  `backend_contract.py` 可对任意 `03_experiment.json` 做契约校验。

### D2 固定流水线，而不是自由 agent 循环

- **问题**：让 agent 自己决定下一步，还是写死顺序？
- **选择**：写死 `plan → literature → experiment → write → review → gates`。
- **否掉的替代**：AutoGPT 式自由规划。否掉的理由是同题两次跑必须可复现：
  自由循环的路径不可复现，答辩时无法回答「这个数怎么来的」。
- **代价**：遇到新题型要人改分支（关联规则改了 4 轮），系统不会自己发现「该换个协议」。
- **证据**：`00_trace.jsonl` 里一次运行的阶段序列是稳定的四段
  （literature 0.0s 复用 / analysis 11.47s / write+review 1169.73s / gates 0.0s）。

### D3 加权分与硬门分离

- **问题**：一个 0~100 的总分够不够决定交付？
- **选择**：`overall` 只做质量信号（P1），交付由 11 道闸门里的 4 道 P0 决定。
- **否掉的替代**：单分数阈值（如 ≥70 即通过）。否掉的理由见 1.3：99.5 分的稿子有 5 条幻觉。
- **代价**：要维护两套判定，且两者会长期不一致（98 vs 76），需要向使用者解释。
- **证据**：`docs/GATES.md` 第 6 节；`07_gate_report.json` 的 `decision.basis`。

### D4 回滚到最优轮，而不是「最后一轮即最终稿」

- **问题**：评审闭环最多跑 3 轮，取哪一轮交付？
- **选择**：每轮留快照 + 分轮 verdict，按 `(分数, -幻觉数)` 取最优；最优不是末轮就回滚。
- **否掉的替代**：默认取最后一轮（大多数流水线的做法）。否掉的理由是实测第二轮会更差：
  第 1 轮 80 分 0 幻觉，第 2 轮 76 分 **2 条幻觉**——「让模型再改一版」不是稳赚。
- **代价**：要维护快照、回滚正文/评审/附件三份产物，逻辑比「覆盖写」复杂。
- **证据**：`REVIEW_ROUNDS.json` 记录两轮分数与回滚决定；
  回滚后 `paper_full.md`、`07_eval_verdict.json`、`paper_full.docx` 三者同源。

### D5 证据落盘，而不是从 stdout 反解

- **问题**：「模型是否真的参与了写作」这个事实从哪里读？
- **选择**：生成器写 `06_paper/WRITE_STATUS.json`（含 `llm_sections`、`model`、时间戳），
  写作代理、交付判定、G03 门三处统一读它。
- **否掉的替代**：解析 stdout 末尾的 JSON（旧实现）。否掉的理由是它真的坏过：
  网关告警混进 stdout 后 `rfind("{")` 解析失败，`llm_written=null`，
  G03 判「未验证」，`07_gate_report.json` 说不可交付，而 `DELIVERY_STATUS.json` 说可交付——
  **两份文件互相矛盾**。
- **代价**：多一个产物要维护；旧运行目录没有这个文件，G03 只能记 `unknown`。
- **证据**：`out_web/task_0001/06_paper/WRITE_STATUS.json` 记录 15 个章节由
  `deepseek-v4-pro` 撰写；同一目录的 `07_gate_report.json` 里 G03 为 `pass`。

### D6 反馈台账带来源与把握程度

- **问题**：评审意见、规则告警、人工批注，能不能平铺在一个列表里？
- **选择**：每条反馈带 `provenance`（rule/model/human）与 `confidence`（high/medium/low），
  排序时 `human > model > rule`。
- **否掉的替代**：只存文本。否掉的理由是模型会误判：评审官把「四舍五入」和
  「题目点名的方法不是最优」都算过幻觉，这类意见不该和硬规则同权。
- **代价**：采集端要判断来源，判断错了会污染统计。
- **证据**：`engine/feedback.py` 的 `TYPES` 与排序；`docs/GATES.md` 第五节。

### D7 模板必须随协议分支

- **问题**：补了新后端，论文侧要不要改？
- **选择**：要改。凡是「协议语义」变化（确定性 vs 随机、有无划分、有无检验），
  模板必须同步分支。
- **否掉的替代**：「产物符合契约就行，论文侧零改动」。这话只在**同一种协议**下成立。
  关联规则是确定性算法，套监督学习模板就会写出「多种子方差」，被 G04 判编造。
- **代价**：每补一类新协议，就要在 `generate_paper.py` 里改 10 处左右（见 BACKENDS 6.1），
  并跑 3~4 轮评审才能收敛。
- **证据**：`docs/BACKENDS.md` 6.1 的改动清单；四轮迭代记录（本文 1.1）。

### D8 模型可替换，且「不可用」是一等状态

- **问题**：模型网关挂了怎么办？
- **选择**：降级为确定性模板稿，并在 `DELIVERY_STATUS.json` 标 `deliverable:false`；
  评审官缺席时 G04 记 `unknown`，严格模式下同样阻塞。
- **否掉的替代**：重试到成功 / 静默降级。否掉的理由是静默降级会把 4 千字的模板稿
  当成 1.6 万字的论文交出去。
- **代价**：网关抖动时用户会看到「不可交付」，体验上不如「假装成功」。
- **证据**：`docs/GATES.md` 6.2 的 `out_gate_real`：G05 给 99 分，G04 因幻觉未通过，
  进程退出码 3；`out_lit_final` 里 4655 字的降级稿被 G02 拦下。

### D9 确定性计算，随机只出现在模型侧

- **问题**：同一题跑两次，结果能不能一致？
- **选择**：数据加载、训练、指标、绘图全部固定种子；LLM 只负责写散文与评审。
- **否掉的替代**：让模型参与算数（例如让它「估计」提升度）。否掉的理由是它会四舍五入、
  会反推、会编边际概率——这三件事在关联规则那轮全部发生过。
- **代价**：新领域必须写确定性实现（Apriori 是纯 Python 手写的），不能直接调模型。
- **证据**：`out_assoc` 与 `out_web/task_0001` 两次独立运行，最优规则都是
  `啤酒→尿布`，`lift=3.8917`、`support=0.2047`、`confidence=0.8893`，完全一致。

### D10 结论的选取规则本身也要写进引擎

- **问题**：有几种评估口径时，报哪一个数当「最优结果」？
- **选择**：图节点分类跑三种特征协议，其中「全图邻居均值」在划分前用了测试折特征
  （传导泄漏）。引擎**只从两种无泄漏协议中择优**，含泄漏的更高值记为上界对照。
- **否掉的替代**：取全局 `argmax` 再说一句「注意有泄漏」。否掉的理由是：
  摘要、结论、表格标题都会引用 `best_method`，只靠提示词提醒挡不住模型把
  0.8641 写成最终结论。
- **代价**：论文 headline 是 0.8515 而不是更好看的 0.8641，需要额外解释取舍。
- **证据**：`_run_graph()` 里 `clean_keys` 的筛选；`graph.leaky_best` 与
  `graph.best_selection_note` 把被排除的数字和原因一起写进事实清单，评审官可核。

这条把本文开头的论点又推进了一步：系统不只约束模型「别写错」，
还决定**什么算数**。约束到「选哪个结果」这一层，才算真的把可信度做进系统。

## 四、一次运行的可审计链

### 4.1 产物 DAG

```
task_spec.json                    题目 → 数据 → 方法 → 评价协议
   │
   ├─ 01_literature.json          文献池（每篇带 confidence 与 llm_usable_in）
   │     └─ 04_literature_review.json   覆盖度 / 缺口主题（回写下轮检索式）
   ├─ 02_hypotheses.json          研究假设（与指标一一对应）
   ├─ 03_experiment.json          ANALYSIS_JSON：metrics / plots / significance / seed_variance
   │     └─ plots/*.png
   ├─ 06_paper/paper_full.md      正文
   │     ├─ paper_full.docx       附件（与正文同源，回滚后重转）
   │     ├─ WRITE_STATUS.json     哪些章节由哪个模型写
   │     └─ REVIEW_ROUNDS.json    每轮分数 / 幻觉数 / 最优轮
   ├─ 06_paper/07_eval_verdict.json   规则评分 + 评审官结论 + 幻觉清单
   ├─ 00_trace.jsonl              阶段、耗时、状态
   └─ 07_gate_report.json         11 道闸门的状态、依据、放行记录
```

### 4.2 复算命令

```bash
python auto_research.py backends --check out_web/task_0001/03_experiment.json   # 契约
python auto_research.py gates   --out out_web/task_0001                        # 裁决
python auto_research.py trace   --out out_web/task_0001                        # 耗时分布
python auto_research.py step    --name eval --out out_web/task_0001            # 只复评
```

`step` 能单独跑，是 D1 的直接结果：评审不需要重跑文献与写作。

### 4.3 一次真实运行的成本结构（`out_web/task_0001`）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 文献（复用缓存） | 0.0 s | 0% |
| 分析（Apriori 全量枚举） | **11.47 s** | 1.0% |
| 写作 + 两轮评审 | **1169.73 s** | 99.0% |
| 闸门裁决 | 0.0 s | 0% |
| 合计 | 1181.2 s | 100% |

这张表本身就是论点：**系统的确定性部分只占 1% 的时间，99% 花在模型上。**
所以优化方向不是「换个更快的分类器」，而是「减少无谓的模型往返」——
例如 `step` 复用产物、回滚而不是无限重写、评审缺席时快速失败而不是重试。

## 五、系统在哪里说过谎（真实失败模式）

架构论证不能只讲设计意图，要讲它失败过的地方。以下每条都发生过，且都留下了产物。

| 现象 | 根因（系统层） | 修法 |
|---|---|---|
| 评审官查出 12 条幻觉，评分门仍判 99 分「优秀」并通过 | 综合段重算 `hard_ok`，把刚设的 `hard_fail` 覆盖回通过 | 幻觉拦截并入最终 `hard_ok`；G04 双保险（原始清单 + 最终标记） |
| `07_gate_report` 判不可交付，`DELIVERY_STATUS` 判可交付 | 「模型是否参与写作」靠 stdout 反解，解析失败即 `null` | 落盘 `WRITE_STATUS.json`，三处统一读它（D5） |
| 回滚只回滚正文，docx 还是差那轮 | 回滚逻辑只处理 md 与 verdict | 回滚后自动重转 docx，三份同源（D4） |
| 表 1 把规则列表写成「各方法主指标对比」 | 模板把「规则」当「方法」，只有一种算法却包装成方法竞赛 | association 专用表头「规则 / 阈值设置」；事实包加硬约束（D7） |
| 网站跑 25 分钟页面一片安静 | 子进程 stdout 块缓冲 | `python -u` 启动子进程 |
| 评审官把正文里**真实的**逐类指标、混淆矩阵、逐折数值判成编造（10 条） | `_ground_truth` 把 `seed_variance` 截到 200 字、且根本没把 `per_class` / `confusion_matrix` 交给评审官；事实清单比正文短，模型写的真数也成了「无据」 | 评审官事实清单补全（逐折、逐类、混淆矩阵全量），并规定配对差值只能原样引用 `paired_tests.diff`，不许用两个四位小数相减推算（0.8641−0.8515=0.0126 与实测 0.0125 差 0.0001） |
| 加一个 MNIST 目录，题库「同领域真实可执行」从 14 掉到 10 | `domain_kw` 放了「卷积 / cnn / 像素 / 图像分类」泛词，叠加 `modality=image` 的 +1 加权，把车辆识别、域迁移、乳腺诊断等题从真正的数据集上抢走 | 新增 `strict_kw`：题目必须点名手写数字才允许匹配；目录不再标 `proxy`。benchmark 恢复 21/33 / 代理 7 / 同领域真实 14 / 误匹配 0 |
| torch 同题两次跑出 0.9665 与 0.9685 | 多线程卷积的浮点归约顺序不确定，只设 `manual_seed` 不够 | `torch.set_num_threads(1)`，两次重跑均为 0.9615；确定性后端要把并行归约也固定住 |
| 反馈台账 113 条、修复率 0 | 只采集不销账，`lessons()` 永远读到同一批 open 条目 | 见 6.2（本轮补的闭环） |

这张表是答辩时最有用的材料：它证明系统不是「设想出来的架构」，
而是被真实故障打磨出来的。

## 六、边界：这套架构不能证明什么

### 6.1 不能保证创新性

系统能保证「说的每句话都有据」，不能保证「这句话值得说」。
第 8 章的创新点仍要人判断：关联规则那轮把「提出框架」改成「采用算法」，
改的是措辞与事实的一致性，不是创新性本身。

### 6.2 评审官也是模型

评审官会误判：实测中把「四舍五入」和「题目点名的方法不是最优」都算过幻觉，
把 12 条压到 5 条靠的是提示词口径，不是换了裁判。
所以 G04 的设计是「评审官 + 规则门」双保险，而不是单独信任任何一方。

反馈闭环此前只完成了「采集 → 归类 → 写作前约束」，没有「销账」：
113 条记录里 80 条是「内容矛盾」，`fix_rate=0`，`lessons()` 每次都在读同一批旧账。
本轮补上 `close_for_topic()`：同题后续运行若 `hard_pass` 且 0 幻觉，
把该题的历史 open 记录标为 `fixed` 并写入 `closed_by_run`。
这样 `stats()` 的修复率才有意义，台账才从「记账」变成「学习」。

### 6.3 新领域仍要人写模板

`association` 从 `hard_fail` 到 `hard_pass` 用了四轮、约一小时。
系统能兜住「说错话」（G04 拦住），但不能自动知道「该怎么说」——
新协议的叙事模板仍然要人写。这是当前架构最大的成本项，也是下一步要沉淀的东西
（把「协议特征 → 模板分支」做成一张表，而不是每次现改代码）。

### 6.4 覆盖范围：7 条后端

分类/回归、文本 TF-IDF、时序、聚类、关联规则、**图节点分类**、**小规模图像分类**。
真图神经网络、目标检测/分割/视频、语义检索与 RAG 仍是缺口；
`backends` 命令会把依赖就绪状态与所需改动列出来。

图节点分类是第二个「菜单外」后端，验证了四接线点不是只为 association 定制的。
它同时也是 D10 的来源：Cora 真实引文网络上跑三种特征协议，最优无泄漏结果为
`逻辑回归｜折内邻居均值` accuracy=0.8515，而含传导泄漏的全图协议给出 0.8641——
系统把后者排除在核心结论之外，只作上界对照。详见 `docs/BACKENDS.md` 第七节。

### 6.5 依赖补齐之后：能力边界变了多少（2026-11-05 实测）

本轮把缺口清单里缺的包装了，并用 `backends --probe`（子进程真导入，不是 `find_spec`）
逐个验证。结果如下：

| 依赖 | 版本 | 冷启动 | 装上之前 | 装上之后 |
|---|---|---|---|---|
| torch | 2.15.0+cpu | 6.93 s | 引擎里的 `PyTorchMLP` 类存在但不可实例化 | 混凝土数据上 R²=0.7011，9.0 s 跑完 |
| torchvision | 0.29.2+cpu | 13.04 s | — | 仅「能 import」，图像分支**未接线** |
| transformers | 5.22.1 | 3.97 s | — | 仅「能 import」，语义分支**未接线** |
| networkx | 3.7 | — | 图后端只能用纯 numpy | 可选依赖就绪，图后端**未接线** |
| xlrd | 2.0.2 | — | `data/_concrete.data` 读不了 | 转成 `data/concrete_strength.csv`，RF R²=0.8988 |

**依赖就绪 ≠ 后端就绪。** torch 之所以立刻有用，是因为 `analysis_engine.py` 里
早就写好了 `PyTorchMLP`（sklearn 兼容包装器），只差一个可导入的 torch；
2026-11-08 又补上独立的 `engine/image_backend.py`，torch 才真正接住图像张量。
而 torchvision / transformers 装完至今**没有任何代码路径使用它们**，
把它们写成「已支持视觉/语义」就是本文开头批评的那种偷换。

同一轮里，P1「领域数据缺失」被真正关掉了：`data/_concrete.data` 是老式 `.xls`，
装上 `xlrd` 后转成 1030×9 的 CSV，加一条目录（标 `proxy`，因为题目要的是等效弹性模量、
数据给的是抗压强度），题目「基于机器学习的复合材料等效弹性性能研究」从不可执行
变成**可执行（代理）**。题库 33 道的可执行数从 18 升到 19，
但**同领域真实数据仍是 14 道**——新增的这条是代理数据，不能算真正接住。

顺带补了一条「代理数据必须自曝」的约束：`proxy_note` 随 spec 进入事实包，
第 3.1 节强制写出「这是代理数据、实际目标是抗压强度而非弹性模量」。
没有它，模型会把抗压强度写成弹性模量——每个数字都对，结论却错了。
这是 D7（模板随协议分支）的又一个实例：**数据性质变了，叙事也必须变**。

## 七、与 nanoMuse 的逐条对照

| 原则 | nanoMuse 的做法 | 本工程的做法 | 差距 |
|---|---|---|---|
| 系统而非模型 | 模型可替换，系统负责身份、路由、执行、审批 | 模型只写散文，系统负责契约、计算、裁决 | 我们的「系统」范围更窄，只覆盖论文生产 |
| 模型可替换 | 多家模型可换 | `_fact_pack` 是唯一接口，换模型只改 `llm_client` | 未做过多模型 A/B |
| 记忆可检查 | 身份/知识/日程存 Markdown，用户可直接改 | `memory/*.jsonl`、`WRITE_STATUS.json`、`REVIEW_ROUNDS.json` 均可手改 | 没有图形化查看器，只能看文件 |
| 执行可审计 | 每步有 trace 与审批边界 | `00_trace.jsonl` + 11 道闸门 + 人工放行留痕 | 我们没有「操作前暂停」的 Sentinel，只有「交付前拦截」 |
| 溯源 | memory provenance 列为 roadmap | 反馈台账 `provenance/confidence`；文献 `confidence` 三档 | 未做到逐句溯源（哪句话来自哪篇文献） |
| 权限边界 | 删除/发送/支付前暂停，按次/按会话/永久授权 | P0 四道闸门；人工放行需 `--who --why`，保留 `raw_status` | 粒度是「整篇论文」，不是「单个动作」 |
| 跨设备 | relay + 各设备本地 runtime | 单机 Web（`web/app.py`），共享包可复制 | 不做跨设备，也不必要 |

**一句话**：nanoMuse 把「个人智能体」从模型里拆出来，我们把「可交付论文」
从模型里拆出来。两者的论证结构相同：**能力在模型，可信在系统。**

## 八、答辩口径（三句话）与复现清单

### 8.1 三句话

1. 这个系统不是在「用 AI 写论文」，而是在**给模型划出可以说真话的边界**：
   算数由确定性引擎做，模型只负责把事实写成散文。
2. 它最重要的能力不是生成，而是**拒绝交付**：四道 P0 闸门拦下过 99.5 分的幻觉稿，
   也拦下过 4655 字的降级稿。
3. 它已经被真实故障改造过：十余条失败模式（`docs/GATES.md` 第七节）、113 条反馈记录、
   四轮 `hard_fail → hard_pass`，每条都能指到产物。

### 8.2 复现清单

```bash
python auto_research.py backends                 # 7 条后端 + 缺口 + 依赖就绪
python auto_research.py backends --probe         # 真导入一遍，测可用性与耗时
python auto_research.py gates --out out_web/task_0001        # 11 道闸门
python auto_research.py trace --out out_web/task_0001        # 成本结构
python auto_research.py feedback --stats         # 反馈台账与修复率
```

对应产物：`out_assoc/`（关联规则，98.3 分）、`out_web/task_0001/`（网站端到端，98.7 分）、
`out_graph_cli/`（图节点分类，94.8 分）、`out_image_cli/`（图像分类，99.2 分）、
`out_gate_real/`（99.5 分但被拒的反例）。
