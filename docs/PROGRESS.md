# AutoResearch 工程现状、能力边界与变更记录

> 本文档记录 AutoResearch 当前的能力边界、已知局限与逐轮修复/升级记录，供开发者与协作方了解工程真实状态。
> 结论先行：**系统可端到端跑通「数据 → 实验 → 中文论文」流水线，产物由真实实验数字支撑；当前主要短板在"论文质量偏模板化 / 文献受网络限制"，而非功能崩溃。**

---

## 1. 这个系统是什么

AutoResearch 是一个**确定性科研流水线**：给定一份 JSON 任务规格（spec，声明数据集 / 候选方法 / 指标 / 假设），系统会自动完成：

1. **文献检索**（可选，无需 API Key）：从 arXiv 公开接口抓取真实可引用文献，写入 `01_literature.json`。
2. **确定性实验**：本地进程直接重跑全部候选机器学习方法，跨 5 个固定随机种子（42–46）统计，计算主指标均值±标准差、混淆矩阵、特征重要性、最优-次优配对显著性检验，并生成图表。
3. **论文生成**：消费上述真实产物，由 LLM（可选）或模板写出中文 Markdown / DOCX 论文，包含摘要、引言、相关工作、方法、结果、讨论、结论与参考文献。

系统对数据集与方法**零硬编码**：换一份 spec 即可产出一篇新的、有真实数字支撑的论文。

## 2. 三种运行模式

| 命令 | 输入 | 说明 |
|------|------|------|
| `run` | 一份 spec JSON | 端到端跑分析 + 出论文（分析不需要 API Key） |
| `plan` | 一句研究主题 | Planner 调 LLM 自动生成 spec + 抓文献 + 出论文 |
| `iterate` | 一句研究主题 | 多轮迭代（扩宽数据集 / 方法）自动出论文 |

纯 `run` 的分析链路**完全不需要联网、不需要 API Key**；只有 `plan`/`iterate` 的"自动写 spec"和"论文 LLM 润色"需要配置 `.env` 里的 API Key。无 Key 时论文回退到模板文本，系统不会崩溃。

## 3. 已具备的能力

- 分类 / 回归 / 聚类三类任务的统一实验框架。
- 5 种子复现、统计显著性检验、特征重要性、假设驱动的"有凭有据"裁决。
- 论文"相关工作"引用**真实 arXiv 文献**（已修复为 HTTPS 端点，规避沙箱对 `:80` 的拦截，见 §5）。
- **数据来源灵活**：除内置 sklearn 数据集外，引擎已支持本地 CSV / Parquet / Excel / Feather 表格文件，以及 OpenML（需联网）。已用一份 569×31 的本地 CSV 实测跑通全流程。
- 中文图表与中文论文（自动探测系统 CJK 字体）。
- 候选方法导入失败时自动记入 `skipped_methods` 并继续，不会把空结果伪装成成功。

## 4. 当前已知局限（诚实列举）

1. **论文质量偏模板化**：生成的论文结构规范、数字真实，但论述深度、创新点提炼、对领域脉络的批判性仍弱于人工写作；本质上是对"实验结论"的规范化表述，而非原创性学术贡献。这是 LLM 润色 + 模板共同决定的，属于"能用但不惊艳"。
2. **文献受网络约束**：arXiv 检索依赖出站网络。若运行环境屏蔽外网（尤其明文 HTTP 80），文献会为空、相关工作章节将退化。已改为 HTTPS（443）以适配多数受限沙箱；若环境完全断网，需预先离线放置 `01_literature.json`。
3. **仅「自动选题」受限于内置集，引擎本身不挑数据**：Planner（LLM 自动把主题转成 spec 那一步）为保证离线可跑、不胡乱选数据，只能从内置白名单（wine / iris / breast_cancer / digits / diabetes）中挑选；但**引擎本身支持任意本地 CSV / Parquet / Excel / Feather 与 OpenML**（已实测本地 CSV 跑通）。因此真实科研场景下，由研究者把自己的数据路径写进 spec 即可，这属于使用方式，不是系统遗留缺口。
4. **方法以 sklearn 生态为主**：内置 XGBoost / LightGBM / PyTorch-MLP 为可选后端（需装对应包），尚未覆盖更复杂的自研模型或大规模训练。
5. **LLM 依赖外部网关**：`plan`/`iterate` 与论文润色依赖 `.env` 中配置的 OpenAI 兼容网关与 Key；网关不可用则退化为模板。

## 5. 本次已修复的问题（相对上一版）

- **文献端点由 `http://` 改为 `https://`**：直接解决"沙箱拦截 export.arxiv.org:80 导致参考文献永远为空"的问题（实测 `:443` 可达）。
- **文献检索加重试与明确报错**：失败不再静默返回空，而是抛出带端点与底层异常的诊断信息，便于排查。
- **补全缺失的示例 spec**：`engine/tasks/proof/wine_sklearn_spec.json`，使 README 示例命令可直接运行。
- **Skill 启动脚本可移植性**：`run_safe.ps1` 不再静默使用构建者机器路径，缺失时给出清晰的环境变量设置指引。
- **修一处随机崩溃（同一课题可能一次成功一次崩溃）**：当假设写作「随机森林与逻辑回归优于其他方法」这类形式时，按比较词切分后只有一段含方法名，裁决变量停在「无」却被直接用于查表，抛出异常并中断整条流水线。该行为取决于大模型当次生成的假设措辞，属高危缺陷。现改为无法裁决时交回关键词路由。
- **修「跨数据集对比」失效**：多数据集结果目录名的清洗规则会把所有中文字符清除成空串再回落到同一个名称，导致各数据集结果互相覆盖、只剩最后一个，跨数据集排名稳定性也因此为空。现改为仅剔除文件名非法字符并保留中文，同名时自动去重。
- **修论文正文的三处脏数据**：假设裁决依据里直接打印了被截断的原始字典；局限性一节写着「以软件沙箱运行模型自主生成的代码」（实为更早架构的残留描述，与本系统事实不符）；「主假设」一节恒为空且交叉引用指向错误小节。均已清理。
- **修中文图表字形缺失**：回归图的 R² 上标字符在首选字体中缺失会渲染成方框，已调整字体优先级。

## 5.1 本轮升级：彻底消除「裁决表—结论矛盾」与「素材未提供」式虚假表述

用户核心诉求：**论文每个数字、每条结论都必须能被实验数据证实，不得出现编造 / 虚假错误**（典型表现：裁决表写「部分支持」而结论段写「证据不足」；正文称「素材未提供第 5.1 节跨数据集对比表」但该节其实有真实数字）。本轮从「确定性裁决」与「LLM 约束」两端同时治理：

1. **裁决表不再反推编造裁决**：`paper/generate_paper.py` 子假设裁决表原先在「分析引擎未给出裁决」时，用结论文本关键词启发式反推出「部分支持」，导致与确定性结论（统一标「证据不足」）互相矛盾。现改为：引擎有真实裁决就采用，否则一律回退为「证据不足」——与结论段永远一致。
2. **结论改为确定性生成**：`paper/generate_paper.py` 新增 `_deterministic_conclusion()`，结论段完全由「证据表 + 真实数字」算出，绝不依赖大模型自由发挥，从根上杜绝「结论支持 / 裁决证据不足」类矛盾。
3. **规划器硬约束子假设可验证**：`planner.py` 的 `_SYSTEM` / `_ITERATE_SYSTEM` 增加「子假设硬约束」——子假设只能点名候选方法声明过的中文名、只能围绕声明的 `metric`（如 accuracy）展开，禁止擅自改用 F1/AUC 等未测指标、禁止提未声明算法（如高斯朴素贝叶斯）。否则下游确定性引擎无法匹配，只能判「证据不足」。
4. **单数据集补齐「两方法标准差比较」裁决**：引擎原只对多数据集做「A 的标准差小于 B」的确定性裁定，单数据集研究里这类最自然的稳定性假设会漏判为「证据不足」。本轮在 `_route_method_comparison` 新增模式 C（含 `_pick_subject_partner` 主语/对手识别），单数据集下也用真实多种子 std 数值给出「支持 / 不支持」。
5. **讨论/深入分析按单/多数据集分流**：`deep_analysis` 与 `discussion` 提示词原先无脑要求引用「第 5.1 节跨数据集对比表 / 排名稳定性表」，单数据集研究中会错把 §5.1 标成跨数据集表并声称缺失（虚假表述）。现按 `task_type` 分流：单数据集只谈 §5.1 主指标对比 + 多种子标准差，并明确「严禁声称存在跨数据集对比表」；多数据集才谈跨数据集排名稳定性。
6. **新增自动化审计脚本 `audit_consistency.py`**：输入一篇 `paper_full.md`，自动抽取「裁决表」与「结论段」每个 H 的裁决并比对，同时检测「错标跨数据集表 / 素材未提供却声称无法」类谎言。回归验证：旧版论文审计报出 `H1 裁决表='部分支持' vs 结论='证据不足'` 矛盾；修复后多轮 `iterate` 产物审计全部通过（裁决表与结论完全一致、无素材谎言）。

**回归验证结果**（本机 `iterate --rounds 2`，全程 `errors: []`）：

| 轮次 | 类型 | 子假设裁决（裁决表 = 结论） |
|------|------|----------------------------|
| round_1 | 单数据集（wine/breast_cancer） | H1/H2/H3 全部由真实 std / accuracy 数值裁定，无「证据不足」漏判 |
| round_2 | 多数据集（葡萄酒/乳腺癌/手写数字） | 跨数据集对比与排名稳定性全部由真实数字裁定 |

即：修复后，论文中**不再出现裁决表与结论矛盾**，也**不再出现把单数据集 §5.1 错标为跨数据集表的虚假表述**；原本会漏判为「证据不足」的假设现在也拿到了真实裁决。

## 5.2 本轮升级：实跑驱动的结果面检查（6 处真实缺陷）

本轮方法不同于「先设目标再找靶」：先实际运行流水线，**逐字通读生成的论文与分析数据**，用真实产出反查缺陷，每处修复都对应产出里一条可见的错误（或自相矛盾）现象，修复后复跑复核该处确已消失。

### 通过阅读产物确证的缺陷

| # | 产出中暴露的真实现象 | 根因 | 修复位置 |
|---|----------------------|------|----------|
| A | §3.3「次要指标为 —。」占位符泄漏到正文 | `spec.secondary_metrics` 为空时直接吐出一个破折号 | `generate_paper.py` 评价协议段：退回到实验里真实测过的指标（如 `f1_macro`） |
| B | 局限性编号错乱成 `1.2.3.4.` 后接 `2.3.` | LLM 把多条局限性塞进一个字符串并自带编号，旧代码只剥掉开头第一个 | `generate_paper.py`：按换行 + 数字边界切分成独立条目再统一编号 |
| C | §6 说「mean concave points（0.7042）等权重极高」，而 §5.3 表的最高是 `worst texture 1.2551` —— 同一篇论文两套结论 | 事实包把整个特征重要性字典 `json.dumps` 后**截断 800 字符**喂给模型，顺序丢失 | `generate_paper.py`：改喂按真实数值降序的 top-K，并显式禁止把中低权重特征说成最高 |
| D | 只跑了乳腺癌**一个**数据集，摘要/§3.1/§3.4 却声称研究「不同特征结构」「跨数据集迁移」 | 规划器首轮 `_SYSTEM` 从不产出 `datasets`，多数据集能力实际不可达 | `planner.py`：话题要求跨数据集时真产出 ≥2 个数据集；单数据集时研究问题收敛到「在本数据集上」 |

注：C 中被 §6 误认为最高的那些**数值本身都是真的**（引擎确实算了 `mean concavity=0.6021`），错的是把中低权重特征当作最高来叙事、与表格矛盾——这正是「数字真实但结论失真」的典型。

### 打通多数据集路径后，实跑暴露的两个引擎缺陷

D 的修复让此前从未被走过的「多数据集」链路真正运行起来，随即在该路径上发现两个真实 bug（均已被真实数据复现并修复）：

1. **跨数据集假设被误判「证据不足」**：假设「SVC 相对 LR 的优势在手写数字上比在鸢尾花上更大」明明可用真实的跨数据集表裁决，却被判证据不足。根因是 `cross_table` 的键是**带括号后缀的完整标签**（`手写数字（高维多类）`），而别名表只返回基名（`手写数字`），查表恒为 `None`；且别名表缺 `鸢尾花` 键。→ `_build_multi_hypothesis_evidence` 改为解析到 `cross_table` 真实键，并按「在文本中出现的先后」排定两个数据集的顺序。
2. **写出假的结论陈述**：假设「随机森林的标准差小于 K近邻」明确点名了两个方法，引擎却输出 `verdict=None` 并断言「未点名具体方法族」——这是一句虚假陈述。→ 模式 A 改为按主语/对手做真实的两两标准差比较给出裁决，无法裁决时的措辞也改为如实说明。

另查出一处**交付包缺陷**：`package.py` 原先用 `basename(dp).startswith("out_")` 排除运行产物，但 `os.walk` 已深入子目录，而子目录名为 `round_1` / `plots`（不以 `out_` 开头），导致运行结果、图表与论文大量混入 zip，交付包从 86KB 膨胀到 1.4MB。已改为在 `dns` 层面剪枝，实测恢复为 86KB / 17 个源文件。

## 5.3 本轮升级：数据层通用化（让任意本地表格真正可跑）

起因不是预设目标，而是实跑验证时发现破绽：README 声称「支持本地 CSV/Parquet/Excel/Feather」，于是构造一份**真实业务形态**的 CSV（300 行，含 `city`/`plan` 两个字符串类别列，以及 40 个缺失值）直接喂给 `run`，结果引擎崩溃：

```
"errors": ["分析失败: 无法加载数据集：could not convert string to float: 'Shanghai'"]
```

根因在 `engine/analysis_engine.py` 的 `_load_file`：末尾无条件执行 `X.values.astype(float)`，把整张表强转成浮点。真实世界的表格几乎必然包含字符串类别列和缺失值——也就是说，**这条声称通用的数据通道，实际上只对"已被清洗干净的全数值矩阵"可用**。这是"感觉通用、实际不可用"的典型。

修法不只是在报错处打个补丁，而是把预处理提升为一层：

1. **统一数据出口**：`load_dataset` 改为返回保留列 dtype 的 `DataFrame`（内部实现拆到 `_load_dataset_inner`），使下游能分辨哪些列是数值、哪些是类别。sklearn / OpenML 来源也一并受益。
2. **混合类型预处理器** `build_tabular_preprocessor`：数值列走「中位数插补 + 标准化」，类别列走「众数插补 + 独热展开」，基数超过 20 的高基数列自动降级为序数编码以控制维度。
3. **零泄漏**：新增统一的 `_fit_prep(X_tr)` 替换全部 8 处硬编码 `StandardScaler().fit(X_tr)`。插补与缩放统计量只在训练折上拟合后作用于测试折——若图省事在全量数据上 fit，论文报告的准确率将不可复现，那等同于伪造结果。
4. **特征名跟随变换**：这是最容易埋雷的一处。独热会把一列展开成多列，若沿用原始 `feat_names` 去 `zip`，`feature_importance` 就会张冠李戴，写进论文就是彻头彻尾的虚假结论。因此拟合后立即用 `feature_names_after_prep()` 换上新列名。同理修正了 Lasso/Ridge 稀疏性统计里的 `total_features`（原本取原始列数，导致「n/m 个系数被压缩为 0」的分数不成立）。
5. **如实披露**：新增 `describe_preprocessing()` 生成逐列报告写入 `03_experiment.json` 的 `preprocessing` 字段，并驱动论文第 4 节生成「特征列预处理明细」表。原先论文那句「数据经标准化等必要预处理后…」属于模板空话，读者无法据此复现，与本工程"不含虚假"的立场直接冲突。

### 一处「半修」及补修

首次验收时发现新逻辑只在单数据集生效：多数据集模式的合并结果里没有 `preprocessing` 字段（子结果当时只保留 best_method/best_value），论文第 4 节仍退回「数据经标准化等必要预处理后…」那句空话——**多数据集恰恰是最需要披露的场景**。已在 `_build_combined` 中汇总 `preprocessing_by_dataset`，并让第 4 节按数据集披露（只列「非平凡」列：有缺失或非数值的列，避免全数值数据集刷出几十行无信息量的表）。

用「含缺失与类别列的本地 CSV + 乳腺癌 + 葡萄酒」混合来源的多数据集 spec 实跑验证，`errors: []`，第 4 节如实渲染：

| 数据集 | 特征列 | 推断类型 | 缺失量 | 预处理方式 |
|--------|--------|----------|--------|------------|
| 真实业务表（含缺失与类别列） | income | 数值 | 25 | 中位数插补 + 标准化 |
| 真实业务表（含缺失与类别列） | city | 类别 | 15 | 众数插补 + 独热编码（4 个取值） |
| 真实业务表（含缺失与类别列） | plan | 类别 | 0 | 众数插补 + 独热编码（3 个取值） |

并注明「乳腺癌、葡萄酒为全数值且无缺失，仅做标准化」。这同时验证了**脏数据 CSV 能与 sklearn 基准数据集放进同一篇跨数据集论文里对比**。

### 实跑验证

真实形态 CSV（6 特征、2 个字符串类别列、40 个缺失值）端到端跑通，`errors: []`，最优方法逻辑回归 accuracy=0.7333。产出核对：

- 预处理报告逐列记录：`income` 缺失 25 → 中位数插补；`city` 缺失 15 → 众数插补 + 独热（4 取值）；`plan` → 独热（3 取值）。
- 特征重要性 top2 为 `score_a`(1.2317) 与 `plan_enterprise`(1.1611)——**与该数据构造时的真实因果一致**（因变量由 `0.8*score_a + 1.2*(plan==enterprise)` 主导），说明预处理未扭曲信号；列名也是独热后的真名而非原始列名。
- 论文第 4 节如实渲染出逐列预处理明细表。

## 8. 本轮升级

> 本轮在「不破坏端到端可跑通」的前提下，重点提升**产出质量**与**结果正确性**。
> 所有改动均已实机验证（见 §8.1），未引入新依赖、未改动运行入口与命令。

### 8.1 已修复的缺陷（影响产出观感与正确性）

1. **规划器按 `estimator` 去重**：此前大模型可能用不同中文名指代同一方法（例如「支持向量机」与「RBF核SVM」都指向 `sklearn.svm.SVC`），会产生重复方法、跨数据集对比表出现空列与重复行。现 `planner.validate_and_fix` 在生成 spec 时即按估计器路径去重，分析引擎 `run_analysis` 再加一层防御性去重。
2. **跨数据集合并剔全空列**：`run_multi_analysis` → `_build_combined` 原本会把「在所有数据集上均无取值」的方法保留为整列空值（表与图中出现一整列 `—`）。现改为在 `cross_table` 构建完成后，剔除这类方法并同步收紧对比表与图表，确保跨数据集对比表列列有数。
3. **论文事实包修复（关键质量项）**：论文生成器的 `generate_paper._fact_pack` 此前读取 `direction / topic / dataset / hypothesis_statement / secondary_metrics` 等**规划器根本不生成的字段**，导致喂给大模型的素材残缺——大模型甚至拿不到数据集名，写作质量被严重拖累。现已改为从真实 spec 结构取值（`task_type`、`data.name` 中文映射、标题、研究问题、子假设列表），大模型写作的信息完整度显著提升。

### 8.2 产出质量增强

4. **第 3.2 节新增确定性方法机理描述**：原本只干巴巴罗列方法名，现已按归纳偏置族（线性 / 树集成 / 核方法 / 近邻 / 正则化等）自动生成每方法的机理说明，降低模板感、增加实质内容（不依赖大模型，零编造）。
5. **假设裁决路由增强**：`_route_method_comparison` 现在能正确处理「X 弱于 / 优于 其他所有方法」「X 最差 / 最优」「明显落后」等断言，无论文中点名几个方法；链式「A 优于 B 优于 C」在比较词切分不干净时退回排序结论，避免混乱文本。子假设裁决表不再截断假设原文到难以辨认。
6. **深入分析提示词强化**：要求大模型必须引用逐类指标 / 混淆矩阵中**表现最差的具体类别名称与数值**，以及多种子标准差与显著性检验的 **p 值**，p 值不显著时必须坦白说明差异不稳健——从机制上减少空话。
7. **文献检索增至 10 篇**（原为 8）：相关工作章节引用更充分。
