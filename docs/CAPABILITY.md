# 能力现状盘点（2026-11-08 实测）

> 这份文件只写磁盘上真实存在、命令能复跑的东西。设想、计划、没验证的都放在最后一节。
> 复核命令：`python auto_research.py backends --probe`、`python benchmark_titles.py`、
> `python auto_research.py gates --out <目录>`。

## 一句话

给一句中文题目，本地确定性引擎跑真实实验 → 生成事实清单 → 模型按清单写中文论文 →
11 道闸门加一个 LLM 评审官判定「能不能交」。**系统的价值不在生成，在拒绝交付。**

## 三、质量闸门（11 道，P0 四项）

- G01 分析层产出有效；G02 正文汉字 ≥6000；G03 模型确实参与写作（`WRITE_STATUS.json` 落盘）；
  G04 评审官已介入且零幻觉。
- 评审官缺席记 `unknown` 而不是 `pass`；`bad_json` 那次实测被 G04 拦成「未验证」，没放水。
- 评审闭环最多 3 轮，按 `(分数, -幻觉数)` 取最优轮回滚，md / verdict / docx 三者同源。
- 横向台账：`00_trace.jsonl`（阶段耗时）、`memory/feedback.jsonl`（113 条反馈、
  同题通过后可销账）、`07_gate_approvals.json`（人工放行留名留理由）。
- 每加一种新协议，模板与事实清单必须一起改。关联规则那轮从 4 次 `hard_fail` 到
  `hard_pass`、图论文 10 条幻觉里 9 条是「事实清单被截断」的假阳性，都写进了
  `docs/BACKENDS.md` 与 `docs/GATES.md`。

## 六、明确还做不到（别写成已完成）

- 目标检测、语义分割、视频理解：要换数据划分和指标定义，不是加个模型。
- 真图神经网络 / 过平滑复现：需要 torch_geometric、层数消融与同领域图数据。
- RAG、知识问答：本质是检索链路加人工评测，硬塞进确定性跑分流水线会跑题。
- 领域数据缺口：网络游戏流失、复合材料等效弹性模量、社交网络推荐等仍是代理数据。
- 创新性、学术审美、导师判断：系统只保证「每句话有据」，不保证「这句话值得说」。
- 语义文本 / transformers：库装好了，但**没有任何代码路径调用**，不算已支持。

## 九、一般本科毕业论文到底能不能做（2026-11-09 复核，用户质疑后的诚实回答）

### 9.1 先把覆盖率的水分挤掉

`benchmark_titles.py` 原来报「33 道真实高校题，21 道可执行（63.6%）」，
这个数字**经不起追问**：

| 口径 | 数量 | 说明 |
|---|---|---|
| 宽口径「可执行」 | 21/33 | 只要技术上能跑就算 |
| 扣掉自测题 | 14/26 | 题库里 7 道标「自测」，是**我们自己出的题自己考**，正是「射标找靶」 |
| 再扣语义不符 | 10/26 | 4 道技术上能跑但题目和数据不是一回事（见下） |
| 再扣代理数据 | **3/26（11.5%）** | 真实高校题 + 同领域真实数据 + 任务语义相符 |

被点名的 4 道语义不符：

- 「基于深度网络的 RGBD 图像分割算法研究」→ 绑到 Olivetti 人脸**整图分类**
- 「图像和视频去雨的高效持续学习技术研究」→ 绑到人脸分类
- 「基于句法信息的文本语义相似性度量」→ 绑到 20 新闻组**主题分类**
- 「基于逻辑回归的信用评分模型」→ 绑到 Adult **年收入是否超过 5 万美元**

原判定只检查模态一致（图像题必须绑图像集），没检查任务语义，
于是「能跑」被写成了「能做」。脚本已补严格复核小节，今后 `python benchmark_titles.py`
会同时打印宽口径与严格口径。**11.5% 是题库命中率，不是系统支持的任务类型数**，
两者不能混为一谈；但它比 63.6% 更接近真实。

### 9.2 一般毕业论文的形态分层

| 类型 | 典型题目 | 本系统 | 原因 |
|---|---|---|---|
| 结构化数据 + 可量化指标的模型对比 | 房价预测、故障诊断、客户分群 | **能接**（本系统的主场） | 有数据、有指标、有方法可比 |
| 用户自带 CSV 的实证 / 问卷 / 计量 | 影响因素回归、满意度分析 | **部分能接** | 能算系数与指标，但「假设检验、稳健性、系数解释」这套叙事模板还没写 |
| 系统 / 软件设计与实现 | 图书管理系统、小程序、推荐平台 | **不能接** | 论文主体是需求、架构、接口、测试、部署；我们的第 4 章固定写「实验数据与候选方法」，套不上 |
| 综述 / 理论推导 / 算法复杂度 | 阻尼随机牛顿法、某方向综述 | **不能接** | 事实清单是数字，不是观点与推导；也不做文献综述写作 |
| 检测 / 分割 / 视频 / 强化学习 / 真 GNN | 车辆识别、去雨、过平滑 | **不能接** | 缺对应评估协议与指标定义，不只是缺模型 |
| 硬件 / 嵌入式 / 仿真 / 案例 / 教学设计 | 电路、机械、质性调研 | **不能接** | 根本没有「数据集 → 指标」这条链路 |

所以用户的直觉是对的：**现在能做的是最标准、最窄的那一类，
大多数普通毕业论文用不上**。系统的准确定位是「可计算实验型论文的自动写作与闸门」，
不是通用毕业论文生成器。

### 9.3 即便在做得到的那一类里，也还有距离

真实毕设通常还要求：自己提出改进并做消融（我们有融合集成，但只是拼方法）、
与近三年方法对比（我们比的是 6 个 sklearn 基线）、在领域真实数据上验证
（7 道代理题就是缺这个）、以及答辩时解释为什么这样设计。
**「能生成一篇格式完整、数字真实的论文」不等于「能过答辩」**，
这个差别不能靠评分掩盖。

### 9.4 要扩到「一般毕业论文」需要什么

按代价从低到高：① 自带 CSV 的实证模板分支（只改模板，最划算）；
② 系统设计类论文的另一套章节骨架（不是补后端，是补一整套叙事）；
③ 检测/视频等新评估协议（最重，见 `docs/BACKENDS.md`）。
前两项都在「论文形态」层，跟模型能力无关——这恰好是架构论证的结论。

### 9.5 一道真实本科毕设题，和我们的论文差在哪

联网核对到的真实选题：河北东方学院人工智能学院、数据科学与大数据技术专业，
《基于线性回归算法的房地产价格走势分析与预测》选题审批表 / 开题报告 / 任务书
（2024-10，指导教师张金良副教授）。同一类题目在本科毕设选题库里成批出现。
这就是本次跑批用的那道题的来源，不是我们为了系统编的。

但把真实开题报告的要求逐条摊开，差距很清楚：

| 真实开题报告要求 | 我们的论文 |
|---|---|
| Django 后端 + MySQL 数据库 + Echarts 可视化 | 没有（论文里没有任何系统实现） |
| 爬虫采集房地产网站数据、数据清洗与缺失值处理 | 用的是公开普查快照，零缺失 |
| 多元线性回归解释「面积、房龄、配套」等影响因子 | 报 6 个模型的 R²，回归系数只作附带 |
| 面向政府 / 企业 / 购房者的应用价值论述 | 只在讨论章泛泛带过 |

**同一道题，人家要做的是一个能跑的系统，我们做的是一组指标对比。**
这就是「一般毕业论文用不上」的具体含义：不是算不动，是论文的形态不一样。
本系统目前能替人完成的是「实验 + 数据分析 + 成文」这一段，
不是「需求、设计、实现、部署」那一段。

## 十、论文类型可插拔：一种引擎，六种论文形态（2026-11-09 新增）

§9.5 指出的核心痛点——「系统/设计型本科毕设做不了」——已通过可插拔论文类型解决。
入口统一为 `--paper-type`（网页端在「论文类型」下拉里提供），所有类型共享同一套
`plan → literature →（可选）experiment → write → eval → gates` 流水线，
只替换「写稿」这一个节点。

| `paper_type` | 形态 | 跑实验 | 章节骨架 | 零编造来源 |
|---|---|---|---|---|
| `method_comparison` | 方法对比型实证 | 是 | 8 章实证骨架 | 实验 JSON 的真实指标 |
| `survey` | 文献综述型 | 否 | 绪论→检索方法→分类框架→研究现状→趋势争论→开放问题→结论 | `01_literature.json` 真实文献 |
| `system_design` | 系统/软件设计型 | 否 | 绪论→需求→架构→模块→关键技术→验证→结论 | `system_spec` |
| `case_study` | 案例研究型 | 否 | 绪论→理论回顾→研究设计→案例背景→案例分析→讨论启示→结论 | `case_spec` + 文献 |
| `technical_report` | 工程实践报告型 | 否 | 概述→需求约束→方案设计→实施过程→结果验证→问题改进→总结 | `project_spec` + 文献 |
| `research_proposal` | 研究方案设计型（开题） | 否 | 背景意义→研究现状→问题目标→内容方法→技术路线→进度成果→结语 | `proposal_spec` + 文献 |

六种形态里只有 `method_comparison` 需要跑确定性实验，其余五种都是
「作者提供素材 → 按骨架成文」，素材由 `spec` 里的对应字段承载。

### 10.1 架构：类型是一份声明，不是一个函数

旧做法（v3 早期）是「每加一种类型就写一个 builder」，加两种之后
`generate_paper.py` 就开始复制粘贴。现在改成两层配置 + 一个统一构建器：

1. **章节骨架**：`paper/thesis_template.py` 的 `PAPER_TYPES`
   ——章节标题、编号、`requires_experiment`、默认 task_type。
2. **写作规格**：`paper/paper_type_specs.py` 的 `TYPE_SPECS`
   ——素材来源（`literature` / `spec_block`）、分批提示词、字段别名、
   确定性兜底文案、附加小节（独立见解 / 研究局限）。
3. **统一构建器**：`generate_paper._build_non_experimental`
   ——读素材 → 分批调 LLM → **字段级兜底合并** → 拼装 → 收尾写 md/docx。

所以现在**新增一种类型只改两处**：注册 `chapters` + 登记一份 `TYPE_SPECS`。
不需要写 builder，不需要动 `eval_agent.py`，不需要动闸门——它们都从注册表读。

### 10.2 素材从哪来：`--spec-extra`

```bash
python auto_research.py plan --topic "某高校教务数据中台建设" \
    --paper-type technical_report --out out_t     --spec-extra my_project.json
```

`my_project.json` 形如 `{"material": {...}}`：含 `material` 字段时，按该类型声明的
`spec_block` 挂到 `system_spec` / `case_spec` / `project_spec` / `proposal_spec`；
其余顶层键直接并入 spec。网页端对应「类型素材（JSON）」文本框，带「填入示例模板」。

### 10.3 类型感知的三处（都从注册表继承，不再硬编码）

- **实验跳过**：`run_task` 对非实验型写一份标记 `paper_type` 的 `03_experiment.json`
  桩，不调用分析引擎。
- **闸门 G01**：按 `thesis_template.is_experimental()` 豁免实验产物硬门；
  G04（零编造）照常生效，事实基础换成该类型声明的素材。
- **评审**：`eval_agent.check_structure` 由 `chapters_for(paper_type)` 生成核心章节集；
  `_ground_truth_for` 按 `spec_block` 取事实基础。新增类型自动获得正确评分口径。

### 10.4 降级策略：宁可拒绝交付，也不编

- LLM 不可用 → 确定性骨架（结构完整、但字数与「非模板」两道门会**正确地拒绝交付**）。
- 某一批写作失败 → 只回填该批字段，前两批成果保留，不整篇崩。
- 素材缺失 → 提示词明确要求「不写而不是补一个合理值」；论文里不留虚构数字。
- **越界引用清理**（确定性护栏）：模型偶尔会「凭印象续编号」（只有 30 篇却写到 [31]–[40]）。
  拼装前用 `_sanitize_citations` 删掉越界编号——宁可少一个编号，也不声称引用了不存在的文献。
- **引用块中性化**：综述/设计/报告型不做实验对比，文献归类块改用「可作参照」措辞，
  不允许出现「与本文直接可比」「在统一实验协议下对照」这类凭空声称的实验关系。
- **数字可溯源**：提示词要求逐句自检「这个数字素材里有吗」，没有就改成
  「以验收时实测为准」「按试点结果确定」；G04 再兜一次底。

### 10.5 实测（`verify_multitype.py`）

```bash
python verify_multitype.py              # 五种非实验类型：建稿 + 闸门 + 结构核对
python verify_multitype.py --eval       # 追加 EvalAgent（含 LLM 评审官）
OPENAI_API_KEY= python verify_multitye.py   # 断网演练：确认走兜底仍不崩、不编造
```

验证口径：结构核对（`structure_checklist_for`）+ 闸门分级（P0 blocking）+
汉字字数 + 评审官幻觉条数。兜底骨架下 G02/G03 报 fail 属预期，
因为「没走 LLM 的模板稿」本来就不该被当成可交付论文。
