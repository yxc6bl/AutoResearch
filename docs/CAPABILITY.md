# 能力现状盘点（2026-11-08 实测）

> 这份文件只写磁盘上真实存在、命令能复跑的东西。设想、计划、没验证的都放在最后一节。
> 复核命令：`python auto_research.py backends --probe`、`python benchmark_titles.py`、
> `python auto_research.py gates --out <目录>`。

## 一句话

给一句中文题目，本地确定性引擎跑真实实验 → 生成事实清单 → 模型按清单写中文论文 →
11 道闸门加一个 LLM 评审官判定「能不能交」。**系统的价值不在生成，在拒绝交付。**

## 三、质量闸门（11 道，P0 四项）

- G01 分析层产出有效；G02 正文汉字 ≥6000；G03 模型确实参与写作（`WRITE_STATUS.json` 落盘）；
  G04 评审官已介入且零幻觉。
- 评审官缺席记 `unknown` 而不是 `pass`；`bad_json` 那次实测被 G04 拦成「未验证」，没放水。
- 评审闭环最多 3 轮，按 `(分数, -幻觉数)` 取最优轮回滚，md / verdict / docx 三者同源。
- 横向台账：`00_trace.jsonl`（阶段耗时）、`memory/feedback.jsonl`（113 条反馈、
  同题通过后可销账）、`07_gate_approvals.json`（人工放行留名留理由）。
- 每加一种新协议，模板与事实清单必须一起改。关联规则那轮从 4 次 `hard_fail` 到
  `hard_pass`、图论文 10 条幻觉里 9 条是「事实清单被截断」的假阳性，都写进了
  `docs/BACKENDS.md` 与 `docs/GATES.md`。

## 六、明确还做不到（别写成已完成）

- 目标检测、语义分割、视频理解：要换数据划分和指标定义，不是加个模型。
- 真图神经网络 / 过平滑复现：需要 torch_geometric、层数消融与同领域图数据。
- RAG、知识问答：本质是检索链路加人工评测，硬塞进确定性跑分流水线会跑题。
- 领域数据缺口：网络游戏流失、复合材料等效弹性模量、社交网络推荐等仍是代理数据。
- 创新性、学术审美、导师判断：系统只保证「每句话有据」，不保证「这句话值得说」。
- 语义文本 / transformers：库装好了，但**没有任何代码路径调用**，不算已支持。

## 九、一般本科毕业论文到底能不能做（2026-11-09 复核，用户质疑后的诚实回答）

### 9.1 先把覆盖率的水分挤掉

`benchmark_titles.py` 原来报「33 道真实高校题，21 道可执行（63.6%）」，
这个数字**经不起追问**：

| 口径 | 数量 | 说明 |
|---|---|---|
| 宽口径「可执行」 | 21/33 | 只要技术上能跑就算 |
| 扣掉自测题 | 14/26 | 题库里 7 道标「自测」，是**我们自己出的题自己考**，正是「射标找靶」 |
| 再扣语义不符 | 10/26 | 4 道技术上能跑但题目和数据不是一回事（见下） |
| 再扣代理数据 | **3/26（11.5%）** | 真实高校题 + 同领域真实数据 + 任务语义相符 |

被点名的 4 道语义不符：

- 「基于深度网络的 RGBD 图像分割算法研究」→ 绑到 Olivetti 人脸**整图分类**
- 「图像和视频去雨的高效持续学习技术研究」→ 绑到人脸分类
- 「基于句法信息的文本语义相似性度量」→ 绑到 20 新闻组**主题分类**
- 「基于逻辑回归的信用评分模型」→ 绑到 Adult **年收入是否超过 5 万美元**

原判定只检查模态一致（图像题必须绑图像集），没检查任务语义，
于是「能跑」被写成了「能做」。脚本已补严格复核小节，今后 `python benchmark_titles.py`
会同时打印宽口径与严格口径。**11.5% 是题库命中率，不是系统支持的任务类型数**，
两者不能混为一谈；但它比 63.6% 更接近真实。

### 9.2 一般毕业论文的形态分层

| 类型 | 典型题目 | 本系统 | 原因 |
|---|---|---|---|
| 结构化数据 + 可量化指标的模型对比 | 房价预测、故障诊断、客户分群 | **能接**（本系统的主场） | 有数据、有指标、有方法可比 |
| 用户自带 CSV 的实证 / 问卷 / 计量 | 影响因素回归、满意度分析 | **部分能接** | 能算系数与指标，但「假设检验、稳健性、系数解释」这套叙事模板还没写 |
| 系统 / 软件设计与实现 | 图书管理系统、小程序、推荐平台 | **不能接** | 论文主体是需求、架构、接口、测试、部署；我们的第 4 章固定写「实验数据与候选方法」，套不上 |
| 综述 / 理论推导 / 算法复杂度 | 阻尼随机牛顿法、某方向综述 | **不能接** | 事实清单是数字，不是观点与推导；也不做文献综述写作 |
| 检测 / 分割 / 视频 / 强化学习 / 真 GNN | 车辆识别、去雨、过平滑 | **不能接** | 缺对应评估协议与指标定义，不只是缺模型 |
| 硬件 / 嵌入式 / 仿真 / 案例 / 教学设计 | 电路、机械、质性调研 | **不能接** | 根本没有「数据集 → 指标」这条链路 |

所以用户的直觉是对的：**现在能做的是最标准、最窄的那一类，
大多数普通毕业论文用不上**。系统的准确定位是「可计算实验型论文的自动写作与闸门」，
不是通用毕业论文生成器。

### 9.3 即便在做得到的那一类里，也还有距离

真实毕设通常还要求：自己提出改进并做消融（我们有融合集成，但只是拼方法）、
与近三年方法对比（我们比的是 6 个 sklearn 基线）、在领域真实数据上验证
（7 道代理题就是缺这个）、以及答辩时解释为什么这样设计。
**「能生成一篇格式完整、数字真实的论文」不等于「能过答辩」**，
这个差别不能靠评分掩盖。

### 9.4 要扩到「一般毕业论文」需要什么

按代价从低到高：① 自带 CSV 的实证模板分支（只改模板，最划算）；
② 系统设计类论文的另一套章节骨架（不是补后端，是补一整套叙事）；
③ 检测/视频等新评估协议（最重，见 `docs/BACKENDS.md`）。
前两项都在「论文形态」层，跟模型能力无关——这恰好是架构论证的结论。

### 9.5 一道真实本科毕设题，和我们的论文差在哪

联网核对到的真实选题：河北东方学院人工智能学院、数据科学与大数据技术专业，
《基于线性回归算法的房地产价格走势分析与预测》选题审批表 / 开题报告 / 任务书
（2024-10，指导教师张金良副教授）。同一类题目在本科毕设选题库里成批出现。
这就是本次跑批用的那道题的来源，不是我们为了系统编的。

但把真实开题报告的要求逐条摊开，差距很清楚：

| 真实开题报告要求 | 我们的论文 |
|---|---|
| Django 后端 + MySQL 数据库 + Echarts 可视化 | 没有（论文里没有任何系统实现） |
| 爬虫采集房地产网站数据、数据清洗与缺失值处理 | 用的是公开普查快照，零缺失 |
| 多元线性回归解释「面积、房龄、配套」等影响因子 | 报 6 个模型的 R²，回归系数只作附带 |
| 面向政府 / 企业 / 购房者的应用价值论述 | 只在讨论章泛泛带过 |

**同一道题，人家要做的是一个能跑的系统，我们做的是一组指标对比。**
这就是「一般毕业论文用不上」的具体含义：不是算不动，是论文的形态不一样。
本系统目前能替人完成的是「实验 + 数据分析 + 成文」这一段，
不是「需求、设计、实现、部署」那一段。

## 十、论文类型可插拔：一种引擎，六种论文形态（2026-11-09 新增）

§9.5 指出的核心痛点——「系统/设计型本科毕设做不了」——已通过可插拔论文类型解决。
入口统一为 `--paper-type`（网页端在「论文类型」下拉里提供），所有类型共享同一套
`plan → literature →（可选）experiment → write → eval → gates` 流水线，
只替换「写稿」这一个节点。

| `paper_type` | 形态 | 跑实验 | 章节骨架 | 零编造来源 |
|---|---|---|---|---|
| `method_comparison` | 方法对比型实证 | 是 | 8 章实证骨架 | 实验 JSON 的真实指标 |
| `survey` | 文献综述型 | 否 | 绪论→检索方法→分类框架→研究现状→趋势争论→开放问题→结论 | `01_literature.json` 真实文献 |
| `system_design` | 系统/软件设计型 | 否 | 绪论→需求→架构→模块→关键技术→验证→结论 | `system_spec` |
| `case_study` | 案例研究型 | 否 | 绪论→理论回顾→研究设计→案例背景→案例分析→讨论启示→结论 | `case_spec` + 文献 |
| `technical_report` | 工程实践报告型 | 否 | 概述→需求约束→方案设计→实施过程→结果验证→问题改进→总结 | `project_spec` + 文献 |
| `research_proposal` | 研究方案设计型（开题） | 否 | 背景意义→研究现状→问题目标→内容方法→技术路线→进度成果→结语 | `proposal_spec` + 文献 |

六种形态里只有 `method_comparison` 需要跑确定性实验，其余五种都是
「作者提供素材 → 按骨架成文」，素材由 `spec` 里的对应字段承载。

### 10.1 架构：类型是一份声明，不是一个函数

旧做法（v3 早期）是「每加一种类型就写一个 builder」，加两种之后
`generate_paper.py` 就开始复制粘贴。现在改成两层配置 + 一个统一构建器：

1. **章节骨架**：`paper/thesis_template.py` 的 `PAPER_TYPES`
   ——章节标题、编号、`requires_experiment`、默认 task_type。
2. **写作规格**：`paper/paper_type_specs.py` 的 `TYPE_SPECS`
   ——素材来源（`literature` / `spec_block`）、分批提示词、字段别名、
   确定性兜底文案、附加小节（独立见解 / 研究局限）。
3. **统一构建器**：`generate_paper._build_non_experimental`
   ——读素材 → 分批调 LLM → **字段级兜底合并** → 拼装 → 收尾写 md/docx。

所以现在**新增一种类型只改两处**：注册 `chapters` + 登记一份 `TYPE_SPECS`。
不需要写 builder，不需要动 `eval_agent.py`，不需要动闸门——它们都从注册表读。

### 10.2 素材从哪来：`--spec-extra`

```bash
python auto_research.py plan --topic "某高校教务数据中台建设" \
    --paper-type technical_report --out out_t     --spec-extra my_project.json
```

`my_project.json` 形如 `{"material": {...}}`：含 `material` 字段时，按该类型声明的
`spec_block` 挂到 `system_spec` / `case_spec` / `project_spec` / `proposal_spec`；
其余顶层键直接并入 spec。网页端对应「类型素材（JSON）」文本框，带「填入示例模板」。

### 10.3 类型感知的三处（都从注册表继承，不再硬编码）

- **实验跳过**：`run_task` 对非实验型写一份标记 `paper_type` 的 `03_experiment.json`
  桩，不调用分析引擎。
- **闸门 G01**：按 `thesis_template.is_experimental()` 豁免实验产物硬门；
  G04（零编造）照常生效，事实基础换成该类型声明的素材。
- **评审**：`eval_agent.check_structure` 由 `chapters_for(paper_type)` 生成核心章节集；
  `_ground_truth_for` 按 `spec_block` 取事实基础。新增类型自动获得正确评分口径。

### 10.4 降级策略：宁可拒绝交付，也不编

- LLM 不可用 → 确定性骨架（结构完整、但字数与「非模板」两道门会**正确地拒绝交付**）。
- 某一批写作失败 → 只回填该批字段，前两批成果保留，不整篇崩。
- 素材缺失 → 提示词明确要求「不写而不是补一个合理值」；论文里不留虚构数字。
- **越界引用清理**（确定性护栏）：模型偶尔会「凭印象续编号」（只有 30 篇却写到 [31]–[40]）。
  拼装前用 `_sanitize_citations` 删掉越界编号——宁可少一个编号，也不声称引用了不存在的文献。
- **引用块中性化**：综述/设计/报告型不做实验对比，文献归类块改用「可作参照」措辞，
  不允许出现「与本文直接可比」「在统一实验协议下对照」这类凭空声称的实验关系。
- **数字可溯源**：提示词要求逐句自检「这个数字素材里有吗」，没有就改成
  「以验收时实测为准」「按试点结果确定」；G04 再兜一次底。

### 10.5 实测（`verify_multitype.py`）

```bash
python verify_multitype.py              # 五种非实验类型：建稿 + 闸门 + 结构核对
python verify_multitype.py --eval       # 追加 EvalAgent（含 LLM 评审官）
python verify_multitype.py --eval --rounds 2   # 评审不过就带意见重写一轮，再复评
OPENAI_API_KEY= python verify_multitye.py   # 断网演练：确认走兜底仍不崩、不编造
```

验证口径：结构核对（`structure_checklist_for`）+ 闸门分级（P0 blocking）+
汉字字数 + 评审官幻觉条数。兜底骨架下 G02/G03 报 fail 属预期，
因为「没走 LLM 的模板稿」本来就不该被当成可交付论文。

### 10.6 评审意见回写：从「拦下」到「改掉」

11-09 下午的实测暴露了一个断点。技术报告型被 G04 判 `hard_fail`，评审官逐条列出
17 处编造：「Airflow 调度每小时一次」「失败任务三次重试后告警」「选取一个完整学期数据
作验收样本」——素材里全没有，但正文一个字都没改。原因是**非实验型构建器根本不读
`04_review.json`**：评审闭环只存在于 `method_comparison` 那条路径上。

现在闭环补齐，四个环节各自负责一件事：

1. **评审端**：指得出原文或数字的幻觉判为硬幻觉，并**强制** `verdict=revise`。
   此前评审官可能一边列出编造、一边仍写 `verdict=pass`，而回滚条件只认 `revise`，
   于是「判了 hard_fail 却永远没有下一轮」。
2. **驱动端**：把意见写成 `04_review.json`。`auto_research.py run` 与
   `verify_multitype.py --rounds N` 共用这一个契约，不是两套逻辑。
3. **写作端**：`_build_non_experimental` 读该文件；`_locate_claims` 用上一版正文把
   每条指控定位到章节（先找引号原句，再找长度 ≥3 的数字，短编号不参与定位）；
   `_review_block` 只把命中**本批字段**的条目下发。这样做的原因很实际：把 32 条指控
   无差别塞进每一批，模型会为了「回应意见」把别章的内容搬进来，改一处坏一处。
   定位不到的条目不作废，作为「通用」条目下发给每一批——宁可多发，不可漏发。
4. **取稿端**：重写后再评一次，按（评审分，-幻觉数）取最优；若最优不是最后一轮，
   正文、`07_eval_verdict.json` 与 docx 一起回滚，三者必须同源。

每批的 `fields` 声明写在 `TYPE_SPECS` 里（15 批全部登记），新增类型时必须一并写，
否则该批会被当成「字段未知」，只能收到全部通用条目。

### 10.6.1 什么时候值得重写（实测给出的答案）

三次两轮实验，同一批演示素材、真实 LLM，结论与直觉相反：

| 类型 | 重写动因 | 第 1 轮 | 第 2 轮 | 结果 |
|---|---|---|---|---|
| 工程报告 | 3 处硬编造 | 9,875 字 / 评审 72 / 幻觉 3 | 13,480 字 / 评审 78 / 幻觉 0 | **留下第 2 轮** |
| 系统设计 | 只有风格建议 | 7,947 字 / 评审 72 / 幻觉 0 | 9,811 字 / 评审 62 / **新增 2 处幻觉** | 回滚第 1 轮 |
| 案例研究 | 只有风格建议 | 11,424 字 / 评审 74 / 幻觉 0 | 12,788 字 / 评审 72 / 幻觉 0 | 回滚第 1 轮 |

「删掉这三处编造」是**可执行的删除指令**，模型照做即可，所以改善；
「写深一点、补论证」没有事实锚点，模型在扩写时反而引入新细节（设计型第 2 轮就
多出 2 处编造，被 G04 判 hard_fail），所以退步。

据此把重写触发条件收紧为**只在评审官指得出具体编造时重写**，风格建议只作为
`issues` 呈现给人看。想强行试验用 `--revise-all`。回滚机制仍然保留：万一第 2 轮
真的更好照样能留下（工程报告那次就是），更差则正文/评审/docx 一起退回第 1 轮。


### 10.7 素材完备度前置检查

零编造的直接后果：素材少一个字段，正文就少一块实质内容，只能靠空话填字数。
等到写完再被评审说「缺乏依据」，已经白花了几分钟模型调用。所以加了一道前置检查
（`paper/spec_check.py`）：

```bash
python paper/spec_check.py --spec out_run/task_spec.json
# [素材] 完备度 53/100（有缺口）：缺的是：交付物；补齐后重跑，正文的实质内容会明显变厚。
# [素材]   缺 project_spec.deliverables（交付物）
# [素材]   薄 project_spec.scope（建设范围（含不做什么））：仅 3 字（建议 ≥15）
```

检查分「必需/建议」两档，结果落 `00_spec_check.json`，构建时打印。
**只提示、不阻断**：素材再薄也照样产出一份结构完整的稿子，但会留痕说明这篇是在
什么素材密度下写的，复核时一眼能看出 75 分是「写得一般」还是「素材就这么多」。


### 10.8 文献摘要接入实验（默认关闭，能力保留）

一次盘点发现，检索结果里其实一直带摘要（综述目录 60 篇中 52 篇有 abstract，
主链路那份 59 篇中 34 篇有），但写作规格写死「你只有题名/作者/来源/年份，
**没有摘要**」，评审官的事实基础也写死「清单不含摘要」。两边一致地把最有用的
真实素材锁在门外——这正是综述、开题、案例研究只能靠题名空转、评审分长期
卡在 60–80 的一个结构性原因。

`paper/lit_abstracts.py` 作为**单一事实源**：写作端的 fact_pack 与评审端的
`_ground_truth_for` 调用同一个 `abstract_block()`，两边逐字同源。只放宽一边是
最危险的——模型能看摘要、评审官看不到，真实转述就会被判成编造。

处理细节：

- 清洗 JATS/HTML 标签、压缩空白、拒绝占位符（"No abstract available"）、
  太短（<40 字）或在句末截断并加省略号；
- 按 `fit_score` 等挑质量高的若干篇，但**输出按引用编号升序**，与
  `build_references` 的连续编号严格对齐，绝不重排编号；
- 预算上限（每篇 300 字、最多 36 篇、整块 9,000 字符）防止把提示词撑爆；
- **数值脱敏**：摘要里的样本量、指标值、记录数统一替换为「〔数值略〕」，
  但保留 `1D-CNN` 这类方法名中的数字（正则只处理独立数字串）；
- 零摘要的文献池自动回到旧版「仅题名」约束，历史产物不回归；
- `WRITE_STATUS.json` 记 `abstracts_used` / `abstracts_available`，可审计。

零编造边界反而更严了：摘要是**别人论文**的结果，不是本文的实验结果；且写作端
与评审端都看不到任何具体数字，正文一旦出现数字就能被事实基础确定性判为编造。
引用摘要内容须用「该文献报告……」「[N] 该研究……」这类带归属的句式；摘要只说
「比较了 A 与 B」就不许扩写成「发现 A 优于 B」。

#### 评审口径也要跟着对齐（实测踩到的两个坑）

第一次接通后，评审分从 88 掉到 83、还多出 3 条「幻觉」，但评审官自己写的判词是
「数字引用正确」「属于转述不规范」「未编造数字」。查下来是两头错位：

1. 把「没写明该文献报告」这种**措辞问题**当成硬幻觉，G04 误拦；
2. 真正的**张冠李戴**（把文献 [44] 的 11 个特征安到 [9] 头上）反而因为
   那个数字确实在事实清单里，被 `_points_at_text` 降级成了软意见。

于是三处一起改：评审提示词明确列出「哪些算幻觉、哪些只算 issues」；
`_points_at_text` 对评审官自述「未编造/引用正确」直接豁免，但对「摘要未提及 /
张冠李戴 / 推断超出」开通硬门通道（不看数字是否在 gt 里）；写作端摘要块加
强制句式要求。三处都有确定性回归用例守着。

顺带补了两个鲁棒性缺口：`chat_json` 解析失败以前直接把评审官判成缺席（G04
未验证、严格模式拒绝交付），现在重试一次并收紧输出要求；`verify_multitype`
以前只看 `blocking`、不看 `unverified`，于是「语义幻觉根本没验证」会被显示成
「全部类型通过」，现在一并计入未通过。

#### 三次实测后定案：数值脱敏

| 轮次 | 做法 | 评审 | 幻觉 |
|---|---|---|---|
| 基线 | 摘要完全不接入 | 88 | 0 |
| 1 | 摘要全量开放（含数字） | 83 | 3（多为「转述不规范」误判） |
| 2 | 修评审口径、压缩摘要预算 | 76 | 2（**真编造**：给没给数字的文献补了「918 条记录」「7 万条」） |
| 3 | 摘要定性可用、数值脱敏 | 72 | 3（首轮甚至只写出 2,934 字） |

第 2 轮的教训最关键：只要摘要里露出一个样本量，模型就会把「可以引用 [8] 摘要
里的数字」泛化成「可以给 [9] 也补一个数字」。这不是提示词能完全压住的，必须靠
**确定性脱敏**把数字从事实包里拿掉。但第 3 轮脱敏后仍不稳，追下去发现了真正的
病根：那两个「编造」的数字其实来自 `_role_citation_block` 拼进正文的 `gist_cn`
（检索阶段落盘的文献一句话概要）——**一直写在正文里，却从未进入评审官的事实基础**。
一告诉评审官「正文严禁数字」，它就把这些真实素材判成编造；脱敏留下的
「〔数值略〕」又让评审官无从核对合理的定性转述。

**因此定案**：`AR_LIT_ABSTRACTS=1` 才启用摘要接入，默认走已验证的零幻觉基线路径。
四轮实测没有一次超过基线，就不该让它成为默认行为；代码、用例与结论都留着，
换更强的模型或更成熟的评审口径可以直接重试。

真正的收获是补掉一个基线就存在的洞：`_gist_gt()` 把 `gist_cn` 纳入事实基础并
注明「属于已提供的真实素材」；`llm_judge` 的判定条款按事实基础里是否真有摘要
动态拼接，默认关闭时不再下发「正文严禁数字」这条会与引用块冲突的口径。
详细实测记录见 `docs/PROGRESS.md` 第 18 节。

### 10.9 一句话概要：把「只给题名」造成的脑补堵住

18 节把 `gist_cn` 补进了评审事实基础，但它**一直没进写作提示的事实包**。
模型写「研究现状」时只看得到题名，于是凭题名替文献编结论。实测证据：

- 案例研究把「测试 8 周体育干预对农村中学儿童心血管风险的影响」写成
  「发现干预方案与学校日程及学生兴趣的匹配程度直接决定了实施质量，
  实质上回应了 SERVQUAL 的响应性与移情性维度」——文献根本没说这些；
- 综述里有 5 篇 `gist_cn` 是占位值「未知」，旧代码会输出成「：未知」，
  模型随后在第 6 章替 [38] 编了一段「讨论了新型监测设备与机器学习的整合」。

`paper/lit_material.py` 把 `gist_cn` 提升为第二份一等素材：

- `gist_items()` 是**单一事实源**，写作端 fact_pack 与评审端 gt 共用同一份
  带编号的条目渲染，逐字同源（延续 10.8 的教训：只放宽一边必出事）；
- `normalize_gist()` 把「未知 / 无 / N/A / 暂无 / unknown」等占位值一律视为缺失。
  `_cite_tail` 在概要缺失时连「（用于：某章）」这种阅读判断也不输出，
  只留题名与出处，不给模型任何可脑补的抓手；
- 写作端约束明确「概要里没写的结论、机制、因果链条一律不得推断补写」，
  数字可引用但须带归属；评审端说明这些数字属于真实素材，不得据此判编造；
- `_role_citation_block` 的结尾按 `neutral` 分流：非实验型不再声称
  「在统一实验协议下重新评估并对照差异」，改为「按角色标注归类，可作方法论参照」。

`topic_overlap()` 用「词的前 5 个字符」做粗粒度主题一致性检查（不需要词干表，
`predict`/`prediction` 都归到 `predi`），结果落 `00_lit_relevance.json`。实测
对口的综述池 0.98、把教育检索式配上心血管池 0.05。**它只预警，不过滤文献、
不改引用编号、不参与闸门**——重排编号会打乱正文 `[N]` 引用，代价远大于收益。
`verify_multitype` 另外修掉一处静默行为：没给检索词时旧版会悄悄复制演示文献池，
现在补了检索词、加了警告与留痕。

**实测（网关恢复后补跑）**：综述用新代码重建，9,868 字、规则 95.2、
独立评审 **87**、**0 幻觉**、11 门全通；同一份旧稿在严口径复评下是 85 分 3 幻觉。
篇幅少了约 2,600 字但零编造——模型不再靠题名替文献编结论，代价是不再靠
脑补把章节撑长，这个交换是划算的。

顺带补了构建子进程的 600 秒硬超时：网关退避重试曾让一次构建挂住十几分钟，
而旧版 `_build()` 完全没有超时。超时会返回 124、自动恢复构建前成稿，
并计入汇总的未通过判定（不会把「重建没跑成、只复评了旧稿」打印成全部通过）。


## 十一、选材留痕、人工偏好与文本诊断（2026-11-10）

### 11.1 能力盘点：哪些本来就有，哪些是这次补的

| 用户要的能力 | 盘点结果 |
|---|---|
| 抓文献 | 已有（`literature_gather_agent`，多源 + 逐篇读 + 角色筛选） |
| 有 Agent 评判抓得好不好 | 已有（`literature_review_agent`：哪些该丢、缺什么主题、该补什么检索式），但以前没读人的偏好，会把人排除的类型又建议补回来 |
| 记录抓了哪些、AI 选了哪些、为什么 | **缺口**：以前只有 02 候选池与 01 入选集两个快照，中间决策与「谁选的」没留痕 |
| 记录用户选了哪些、偏好存记忆 | **缺口**：`feedback --add` 能记问题，记不了偏好；单条人工意见要攒够两次才生效 |
| 根据用户反馈改进下轮抓取 | 部分已有（补抓闭环、历史被引用加分），但没有结构化的偏好入口 |
| 整篇产出后有评审 Agent | 已有（`eval_agent`），但产物是给机器看的分数与碎片 issue |

| 评审意见的反馈与记忆 | 部分已有（问题入台账、重写闭环），但人无法对单条意见表态 |

### 11.2 新增：选材台账 + 跨运行偏好

`engine/selection_ledger.py` 分三层，不混在一起：

- **本次台账** `<out>/LIT_SELECTION.json`：候选池里每一篇的去留、理由、决策者
  （`model` / `rule` / `human`），以及审评 Agent 回填的弱相关与缺口。
  补抓会覆盖 01 但不更新 02 候选池，所以台账会把「入选却不在旧候选快照里」的
  文献补记进去（实测 59 篇入选、27 篇来自补抓），保证 `selected` 条数与入选数一致。
- **跨运行偏好** `memory/lit_preferences.json`：`avoid` / `require` / `boost` 规则
  （按 id、题名、来源、年份、关键词匹配）、单篇 `keep` / `drop`、评审批注。
  **单条立刻生效**，不必等反馈台账攒够两次。
- **应用时机**：抓完、写正文之前，只剔除与加分，**不重排顺序**——顺序决定正文
  `[N]` 引用编号。`keep` 优先于 `drop` 与排除规则。

`lit-pref` 子命令是人工入口；文献审评 Agent 与写作事实包都会读到 `preference_prompt()`，
避免「人明确不要的类型被当成缺失主题建议补回来」这种自相矛盾的反馈。

### 11.3 新增：文本级诊断 Agent

`agents/paper_review_agent.py` 通读全文，产出 `06_paper/08_paper_review.md`（给人读）
与同名 json。**不出现分数**，只给：

- `verdict`：能不能交的四档文字判断；`overall`：整体水平与最影响质量的 2–3 件事；
- `chapters`：逐章判断 + 问题清单，每条含 `quote`（必须逐字出现在正文）、
  `why`、`how`（可执行动作，不许写「建议加强」），带稳定编号 P01、P02…；
- `top_actions`：按影响排序的优先修改清单。

确定性护栏：编造的定位句（正文里找不到）直接删除；网关不可用时报告明确写
「未完成文本诊断（网关不可用）」，只列数得出来的事实，不假装模型读过全文——
实测第一版兜底把封面、诚信声明、英文 Abstract 当成「展开不足」，已修。

**闭环**：诊断动作自动入反馈台账；人用
`lit-pref --review-mark <目录> P01 accepted|rejected --note "…"` 对单条表态；
采纳/驳回写进偏好记忆，`review_notes_for()` 在下一轮写作提示里以最高优先级注入
（被驳回的意见会明确要求「不要再按它改」）。主流水线写稿后自动跑诊断，
`step --name review` 可单独重跑，`AUTO_PAPER_REVIEW=0` 可关闭。

### 11.4 实测状态（如实说明）

- 端到端演练：选材台账写出 1046 候选 / 59 入选、审评缺口回填成功；
  偏好与批注写入后，确认两者真实出现在写作事实包里。
- 诊断书的**规则兜底路径**已跑通；**模型通读路径**因网关自 19:46 起持续限流，
  本轮未取得真实诊断结果，恢复后执行
  `python auto_research.py step --name review --out <产物目录>` 即可。
- 回归用例增至 59 个，全部通过（0.15 秒、不联网）。

### 11.5 补齐：检索规划留痕、网页人工选材、自我反馈闭环

用户把设想又讲细了一层：拿到选题后要先「判断抓什么、走什么路径」，这一步要留痕；
「人也要能有选的权利」，不能只让 AI 选完事；评审的 feedback 要能存记忆、让系统
自己改进。对照上一节的实现，这三件确实还差，本轮补齐。

**检索规划台账** `engine/lit_plan.py` → `<out>/LIT_PLAN.json`：

- `understanding`：选题、任务类型、方法线索、数据集线索（直接来自任务规格，不推断）；
- `strategy`：每条检索式 + 用途分类 + 来源（`planner` / `feedback` / `refetch` /
  `broadening`）、启用的数据源、是否由模型规划。用途是确定性词面推断，
  明确标 `purpose_source="keyword_heuristic"`，**不冒充模型的推理过程**；
- `rounds`：首轮广撒网、覆盖不足扩面、审评缺口补抓，各自用了哪些式子、抓回多少；
- `outcome`：候选数、入选数、剩余缺口。

**网页人工选材**：`GET /api/lit-choices?dir=…` 返回 AI 入选清单与每篇状态，
`POST /api/lit-choices` 批量写回。前端在「文献」标签加了勾选面板：默认全选，
取消勾选即剔除，可填备注；保存后 `apply_human_choices()` 同时写偏好记忆和本次
选材台账（标 `by=human`、记录 `human_choices`）。接口限制只能访问工程根内目录，
实测越界请求被拒。旧目录没有检索计划时前端明确提示，不显示成空白。

**自我反馈闭环**：

```
论文诊断 / 文献审评  →  suggested_queries / recommended_add_queries
    → add_feedback_queries()  存进 memory/lit_preferences.json
    → 下轮抓取 take_feedback_queries()（只消费一次）
    → 并入 queries，LIT_PLAN 标 origin=feedback
    → 该轮诊断书显示「本次检索已应用的历史反馈」
```

另外诊断 Agent 只对模型真通读的结果存检索建议，规则兜底不配给建议（避免污染
计划）。人工表态的匹配也收紧了：短标识必须精确等于文献 id 或题名，长度 ≥8
才允许子串命中——实测单字符标识会因为题名里含同一个字母，把「人工剔除」
错误豁免成「保留」。

**实测**：网页 GET 返回 59 篇入选清单、POST 剔除 1 篇后台账 `by=human` 增 1、
偏好文件写入成功；越界目录被拒。64 个回归用例全部通过（0.3 秒、不联网），
覆盖反馈检索式只消费一次、计划标来源、诊断书显示已应用反馈、人工勾选改台账。
网关仍限流，本轮未跑真实抓取，因此 `LIT_PLAN.json` 只在新一次抓取时生成，
旧目录会明确显示「未记录检索计划」。详见 `docs/PROGRESS.md` 第 21 节。
