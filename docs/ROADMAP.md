# 通用化路线图：从「表格 ML 实验」到「任意实证研究」

本文档回答一个问题：**这个工程现在只能写分类 / 回归 / 聚类三类论文，要让它能写更多、乃至"通用的"论文，路要怎么走、要多久、哪些不该做。**

所有结论都基于当前代码的实测量，不是估算。

## 1. 先说结论

**「什么论文都能写」是错误的目标。** 这个工程真正的资产不是"能写"，而是"**写出来的每个数字都能被复算验证、每条结论都不与证据矛盾**"。一旦扩张到无法做确定性验证的领域，这个核心优势立刻消失——那不是升级，是自毁。

正确的目标是：**内核保持与领域无关，把领域差异收敛到可插拔的适配器**。边界可以一步步往外推，但每一步都必须带着"不含编造"这条底线一起走。

## 2. 现状盘点（代码实测量）

| 层 | 职责 | 现状 | 代码证据 |
|---|------|------|---------|
| 1 通用内核 | 确定性执行 → 证据裁决 → 事实注入 → 一致性审计 | **已通用，与领域无关** | `_route_method_comparison`、`_build_multi_hypothesis_evidence`、`_fact_pack`、`audit_consistency.py` |
| 2 数据适配 | 把任意数据喂成可用矩阵 | **本轮打通混合类型表格** | `build_tabular_preprocessor` / `describe_preprocessing` |
| 3 任务适配 | 认定"这是一个什么任务" | **硬编码三选一** | `"regression"`/`"classification"` 字符串 21 处，`is_reg`/`is_cluster` 分支 8 处 |
| 4 评测适配 | 指标、显著性、方差口径 | **硬编码** | 指标相关字符串引用 57 处 |
| 5 写作适配 | 论文章节骨架 | **单一模板写死** | `generate_paper.py` 中 12 个固定小节写死 |

第 1、2 层已经与领域无关，这是好消息：**第 3–5 层是纯粹的工程解耦问题，不受 AI 能力上限约束，工作量是可预期的。**

## 3. 分阶段路线

### 阶段 A — 评测通用化（约 1 周）

现阶段 accuracy / f1_macro / r2 / mse 等具体指标名直接写死在代码里（相关字符串引用 57 处），换一个指标就要改代码。做法：把指标改成**注册表 + 声明式 spec**（`metric: {name, fn, direction, higher_is_better}`），任何 `(y_true, y_pred) -> float` 的函数都能注册。

- 收益：立刻支持 AUC、F1 per class、RMSE、MAPE、NDCG、编辑距离等任意指标，且**自动获得现有的 "裁决表 = 结论" 一致性保证**。
- 风险低：不动执行主干，只替换查表。

### 阶段 B — 任务适配接口化（约 2–4 周）

把 `run_analysis` 里散落的 `if is_reg / if is_cluster` 收进 `TaskAdapter` 协议：

```python
class TaskAdapter:
    def load(spec) -> DatasetBundle      # 数据怎么读
    def split(spec, seed) -> folds       # 怎么切分（随机 / 时序 / 分组 / 交叉验证）
    def evaluate(y_true, y_pred) -> dict # 怎么算分（走阶段 A 的注册表）
    def artifacts(...) -> dict           # 出什么图、什么明细（混淆矩阵 / ROC / 残差图）
```

已支持的三种任务改成内置 adapter；新增任务只需写 adapter：

- **时间序列**：滑窗切分 + 时序-aware 指标（MASE、sMAPE）+ 避免未来信息泄漏 → 1 周
- **文本分类**：TF-IDF / embedding 特征 + 宏 F1 → 3–5 天
- **图像分类**：torchvision 后端 + top-k 准确率 → 1 周
- **图学习 / 推荐 / 排序**：各自约 1 周

每加一个 adapter，上限就往上一格，内核一行不动。

### 阶段 C — 论文骨架可插拔（约 1 周）

把 12 个写死的小节改成由 spec 的 `paper_template` 驱动；内置 `ml_empirical`（现状）、`systems`（系统类：强调实现与开销）、`ablation`（消融类）等骨架。注意**结论与裁决仍由确定性逻辑生成**，模板只管章节组织，不碰是非。

### 阶段 D — 非实验型论文：明确不建议做

综述、纯理论推导、数学证明类论文走的是**完全不同的流水线**（检索 → 综合 → 论证 → 反驳），没有"实验产物"可供验证。好处也清楚：**今天这套"不编造"的保证在那里基本失效**——没有可复算的证据，就只能靠模型自律，这正是当前系统一直在修补的失效模式。真要做，应当从"辅助写作工具"定位出发（人负责论证正确性），而不是打着"自动生成可发表论文"的旗号。

## 4. 关于「两天内能不能完成」

分两档说清楚：

- **表格类 ML 实证研究做到通用（阶段 A + B 的表格部分 + C）**：约 1–2 周业余投入，属于确定性工程。**这部分覆盖了绝大多数"跑实验写论文"的需求**，包括你自己拿业务 CSV 来做。
- **连 NLP / CV / 图学习 / 时间序列都覆盖**：加 3–5 个 adapter，每个 3 天–1 周，合计约 1 个月业余投入，**没有未知风险**，因为每个 adapter 都可以像乳腺癌数据集那样实测验收。
- **"什么论文都能写"含理论类**：不建议，理由如上；且坦白说，让系统自动产出有原创理论贡献的论文，超出了当前模型的能力边界，做成只会产出"看起来像论文的文本"，与本项目"不含虚假"的立场直接冲突。

所以如果要把这条路走扎实，我建议的顺序是 **A → C → B**：先把指标和骨架做成可插拔（风险最低、收益最快），再逐个加任务 adapter（每加一个都实跑验收）。

## 5. 每阶段的验收标准（不得跳过）

沿用本工程已建立的工作纪律，任何新增能力必须：

1. 实跑 ≥2 个真实场景，全程 `errors: []`；
2. 跑 `audit_consistency.py`，要求裁决表与结论完全一致、无"素材未提供"式虚假表述；
3. 论文里的每一个数字都要能在 `03_experiment.json` 里指到出处；
4. 补一条 `docs/PROGRESS.md` 记录。

做不到第 2、3 条的适配器，不允许合入。
