# 明天汇报用的技术要点

> 用途：和老师当面讲这套系统时，按「一句话结论 → 原理 → 证据」三层说。
> 所有数字都来自当前工程的实际产物，不是估计值。

## 0. 一句话定位

这不是「让大模型写一篇论文」，而是**把论文生产拆成一条可验收的流水线**：
每个阶段都留下产物，每个结论都能追到证据，不合格就拒绝交付。

---

## 1. 系统怎么跑（30 秒版）

`python auto_research.py plan --topic "..." --paper-type survey --out out_xxx`

| 阶段 | 做什么 | 留下什么 |
|---|---|---|
| 规格 | 把主题解析成任务规格（数据、方法、指标、子假设） | `task_spec.json` |
| 文献 | 规划检索式 → 六源抓取 → 去重打分 → 语义筛选 → 覆盖审评 → 补抓 | `LIT_PLAN.json`、`01_literature.json`、`04_literature_review.json` |
| 实验 | 确定性跑多方法、5 个随机种子、分层交叉验证、配对检验 | `03_experiment.json`、`plots/` |
| 写作 | 按章节分批调模型，事实包约束，禁止素材外数字 | `06_paper/paper_full.md`、`WRITE_STATUS.json` |
| 评审 | 规则六维评分 + 模型评审官查幻觉 → 有问题回滚重写 | `07_eval_verdict.json`、`REVIEW_ROUNDS.json` |
| 诊断 | 专家式通读：逐章问题、改法、范文差距 | `08_paper_review.md/json` |
| 闸门 | 11 道门按 P0/P1/P2 裁决 | `07_gate_report.json`、`DELIVERY_STATUS.json` |

## 2. 八个可以主动讲的点

### 点 1｜流水线而不是一次性生成

**一句话**：把「写论文」拆成七段，每段都有输入、输出和失败处理，任何一段坏了都能定位。

**原理**：阶段之间只通过落盘文件交接（spec → 文献 JSON → 实验 JSON → 正文 → 评审 JSON → 闸门报告），
所以可以单段重跑、单段替换、事后审计。模型只在「写作」和「评审」两段出现，
数据、实验、裁决都不经过模型，避免模型既当运动员又当裁判。

**证据**：一次完整跑产生 14 项产物；`00_trace.jsonl` 记录每阶段耗时与状态；
91 个回归测试覆盖链路（`python -m unittest discover -s tests`，约 0.6 秒，不联网）。

**老师可能问**：为什么要拆这么细？
**答**：不拆就无法判断「论文不好」是数据错、实验错、写作错还是评审错；拆开之后每段都有可核对的产物。

---

### 点 2｜零编造：靠事实基础同源，不靠提示词

**一句话**：论文里的每个数字都必须能在实验产物里找到，写作端和评审端看的是同一份事实。

**原理**（三层）：
1. **数字只来自确定性实验**：方法对比、逐类指标、混淆矩阵、特征重要性、数据规模全部由
   `analysis_engine` 实跑后写入 `03_experiment.json`，写作提示词明确禁止引入素材外数值。
2. **写作/评审同源**：评审官拿到的事实清单 `_ground_truth_for(...)` 与写作端事实包来自同一套
   生成函数（文献一句话概要、摘要节选、指标表都逐字一致），不会出现「评审说正文数字是编的，
   其实那个数字是真的」这种误判。
3. **文内交叉校验**：`audit_consistency` 抽取「裁决表」与「结论」中的同一子假设结论，
   不一致直接判硬伤；再叠加评审官逐条幻觉清单。

**为什么不能只靠提示词**：模型会「顺着写」，提示词说「不许编」并不能阻止它补一个看起来合理的数字；
只有把可用事实做成封闭清单，再用独立一端去比对，才能把「编造」变成可检测事件。

**证据**：G04 是 P0 门，判据是「评审官已介入 + 无幻觉 + consistency=100」，
权限写的是「系统拒绝，不接受放行」。历史跑批里出现过评审 72 → 78、幻觉 3 → 0 的回滚重写记录。

**老师可能问**：能保证绝对不编吗？
**答**：不能保证语义真值，只能保证「不超出给定素材」；素材本身错了，系统查不出来。这是边界。

---

### 点 3｜评审要分两种：规则合规分 ≠ 论文质量分

**一句话**：以前 93 分的烂论文，问题就出在把「格式合规」当成了「写得好」。

**原理**：
- **规则评分**（`eval_agent`）是六维加权：选题 12%、文献 15%、结构 10%、
  方法与内容 33%、创新 15%、撰写规范 15%，通过线是 `overall ≥ 60` 且零编造硬门满分。
  它查的是「有没有」：章节齐不齐、引用编号对不对、篇幅够不够、数据是否自洽。
- **专家评审**（`paper_review_agent`）不给分数、不给等级，只回答「写得好不好」：
  论证是否成立、证据是否支撑结论、文献是否真的被用起来、有没有独立见解、文字是否可读。
  输出逐章问题（`quote` 必须逐字可查、`why`、`how` 必须可执行）和按影响排序的 `top_actions`。
- 两个结果分开存：`overall` 标为 `rule_compliance`，另设 `quality_assessment.status`
  标明模型评审到底做没做。网页上「综合评分」已改称「规则合规分」，并固定提示「规则分≠论文质量」。

**证据**：五类历史产物规则分 84.5–96.8，模型评审 70–87，两者经常不同向；
其中工程报告规则 85.2、模型只给 70，说明规则分确实会高估。

**老师可能问**：那还要规则分干什么？
**答**：规则分做「准入筛查」和回归测试，成本低、可复现；质量判断交给专家评审，两者职责不同。

### 点 4｜用高质量范文做「参照系」，不是训练模型

**一句话**：把清北等高校优秀论文的可观测特征抽成一把尺子，注入评审提示词，让模型按同一标准判断。

**原理**：
- `benchmark_corpus.extract_fingerprint()` 从范文里抽**确定性信号**：汉字数、章节数、
  参考文献数、顶刊/顶会出现、原创性表述、独立创新小节、公式信号、图表引用、
  消融/超参寻优、跨数据集、显著性检验、多种子、论证连接词密度（每千字）。
- `reference_profile()` 把这些信号聚合成「范文典型水平」，连同评阅要求一起拼进专家 prompt；
  `quality_gap()` 在网关不可用时也能给出可核对的差距，不会只剩一句「未完成诊断」。
- **不是微调**：没有训练、没有改模型权重，全部是规则抽取 + 提示词参照。这样可解释、可替换、
  不依赖 GPU，也不涉及范文版权之外的训练使用。

**证据**：当前可读范文是北大 2024 本科毕设，23,868 汉字、5 章、135 篇参考文献、
11 处公式信号、87 处图表引用、每千字 2.68 个论证连接词。用它量一篇 9,868 字的综述：
篇幅、文献量、公式、图表引用都明显偏少——这正是「能看出差距」的价值。

**老师可能问**：样本只有一篇，靠谱吗？
**答**：这是当前最大的局限。机制已经跑通，但标尺的统计意义需要更多范文；
`corpus/README.md` 写明了扩展方式：放可读的中文 `.txt` 即可，下一轮自动纳入。
另外清华那篇 `.txt` 是 PDF 提取失败的乱码（汉字数为 0），已被自动剔除，不会污染标尺。

### 点 5｜选材有判断、有留痕、有记忆

**一句话**：不是「搜到什么用什么」，而是先决定抓什么、为什么抓，再记录谁选了谁、为什么。

**原理**：
1. **检索计划** `LIT_PLAN.json`：记录选题理解（任务类型、方法、数据集线索）、
   每条检索式的用途与来源（planner / feedback / refetch / broadening）、启用数据源、每轮抓回量。
   用途分类是关键词 heuristic，字段里明确标 `purpose_source="keyword_heuristic"`，不冒充模型推理。
2. **候选 → 入选台账** `LIT_SELECTION.json`：每篇记 `selected`、`by`（model / rule / human）、
   理由；候选池和补抓后的入选集都会补齐，避免「入选 59 篇、台账只记 32 篇」。
   相关性映射是确定性的：直接可比 0.95、方法可借鉴 0.72、背景 0.40、未知 0.30、无关 0。
3. **偏好记忆** `memory/lit_preferences.json`：三类规则 `avoid`（命中即剔除）、
   `require`（优先选）、`boost`（加分），加上单篇 keep/drop 和评审意见，单条立即生效。
   网页「人工选材」面板勾选后写回，台账同步标 `by=human`；下一轮检索直接带上。

**证据**：技术报告那次跑批，候选池 1,046 篇 → 入选 59 篇，台账逐条可查；
评审 Agent 给出的覆盖缺口会转成补强检索式，存记忆后下一轮并入。

**老师可能问**：模型选错了怎么办？
**答**：人可以逐篇勾选覆盖，且覆盖会进偏好；模型决策、规则决策、人工决策在台账里分开标，
事后能看出是哪一环的判断出了问题。

### 点 6｜失败要「拒绝交付」，不能「假装成功」

**一句话**：网关挂了、模型没参与写作，系统要明确告诉你「这不是成稿」，而不是给一份看起来完整的稿子。

**原理**：
- **总开关**：`available()` 探测模型可用性；只要有一条通道可用就走模型，全挂才降级。
  探测失败会逐条切换已配置通道（主 + `_2` + `_3`），不会只探主通道就判死。
- **降级路径**：模型不可用时写作退回确定性模板骨架，`WRITE_STATUS.json` 记 `llm_written=false`；
  G02（正文 ≥ 6000 汉字）与 G03（模型参与写作）是 P0 门，直接判 `deliverable=false`。
  网页结果页出现红色「这不是可交付成稿」横幅。
- **韧性参数**：调用最多重试 4 次，指数退避 3s 起、封顶 25s、带抖动；
  连续失败 3 次尝试切备用通道；熔断器连续失败 4 次开路、冷却 120 秒；
  可用性负缓存只保留 30 秒，避免一次握手超时把整个进程判死。
- **接口无关**：规划、写作、评审三处调用统一走 `create_chat`，推理模型（o1/o3/gpt-5 等）
  自动改用 `max_completion_tokens` 且不传 `temperature`；空 `extra_body` 不发送；
  端点报「参数不认识」时先丢额外请求体、再切参数风格自动重试。

**证据**：学校网关 502 那次，完整流程仍以退出码 0 跑完、产物齐全，但闸门判
`deliverable=false`、G02/G03 阻断——这是护栏在起作用，不是崩溃。
本地假端点实测：主通道 502、备用正常时，全新进程 `available()=True` 并自动接管。

**老师可能问**：降级稿有什么用？
**答**：只用于自测和定位链路，不用于提交；它的存在是为了让「哪一段坏了」可见，而不是交付假成品。

### 点 7｜文本体检：把「读起来不对」变成可枚举的硬规则

**一句话**：这是组员这版新增的模块，专门抓模板稿和模型稿里最常见的文字硬伤。

**原理**：`paper/text_lint.py` 是纯标准库的 Markdown 检查器，12 条 FAIL + 2 条 WARN：
- C1 未解析占位符（`TODO`、`[[MISSING:]]`、花括号模板字段）
- F1 正文出现内部术语（引擎、规格、证据字段、确定性分析、pipeline、配置项）
- G1 英文标题误用中文书名号《》
- A1 段落以虚词/指代词开头（的、而、与、和、在、是、也、但、其、该、对、为、则、并、以、这、那）
- A2 段落缺句末标点
- B1 连续标点；B2 中文字符间多余空格；B3 连续重复词
- D1 引用块标记未清理；D2 行首井号不是有效标题；D3 粗体标记未配对；D4 表格分隔行不在表格中
- E1（WARN）同一方法清单重复出现；H1（WARN）章节字数低于下限的 80%

结果写 `LINT_REPORT.json`，`lint_fail` / `lint_warn` 进 `WRITE_STATUS.json`；
设 `PAPER_LINT_STRICT=1` 时，有 FAIL 直接让构建返回非零。

**证据**：组员用模板骨架跑出的那篇，体检抓到 13 个 FAIL（11 个 A2、2 个 A1）和 6 个 H1 WARN。
这正好证明「语义不通」不是玄学：段落没有句末标点、以虚词开头，读起来就是断句和残句。

**老师可能问**：规则能代替人读吗？
**答**：不能。它只抓形式硬伤，抓不到论证是否成立；所以它和专家评审是互补，不是替代。

### 点 8｜可复现、可审计、可交接

**一句话**：同一份规格、同一个随机种子，应该跑出同一组数字；任何人拿到产物都能追溯到哪一步。

**原理**：
- 实验固定 5 个种子 `[42, 43, 44, 45, 46]`、分层交叉验证、配对 t 检验；
  数据划分与预处理都在训练折内拟合，避免信息泄漏。
- 每阶段写 `00_trace.jsonl`；选材、检索、评审、闸门各有独立 JSON；
  论文正文与 Word 同时落盘。
- 工程侧：91 个回归测试不联网；网页只用标准库；
  `/api/open` 与 `/api/file` 限定在工程根内（越权路径返回 403/404）；
  模型接口可换任意 OpenAI 兼容端点，不绑定厂商。

**证据**：五类论文全部 `hard_pass`、`deliverable=true`：
综述 9,868 字 / 规则 95.2 / 模型 87；系统设计 7,947 / 93.9 / 82；
案例 12,788 / 84.5 / 76；工程报告 13,480 / 85.2 / 70；开题 10,238 / 96.8 / 75。

**老师可能问**：这些分数能说明什么？
**答**：只说明「在这套规则下合规」，不说明达到发表水平；真正的质量判断要看专家诊断和人工审阅。

## 3. 五分钟讲述顺序（建议）

1. **先给结论**（30 秒）：我们做的是一条可验收的论文生产线，重点不是生成，而是「能判断哪一步不可信」。
2. **画流水线**（1 分钟）：七个阶段，每段产物是什么。
3. **讲零编造**（1 分钟）：事实基础同源 + 文内交叉校验 + P0 门不接受放行。
4. **讲双轨评审**（1 分钟）：规则合规分 vs 专家质量诊断，为什么必须分开。
5. **讲范文标尺与选材记忆**（1 分钟）：参照系怎么来、选材怎么留痕、偏好怎么生效。
6. **收尾**（30 秒）：当前限制与下一步——真实模型成稿、范文库扩充、可审计模块接线。

## 5. 老师可能追问（照着答）

1. **「这不就是让 AI 写论文吗？」**
   不是。模型只负责写作和评审两段，数据与实验是确定性代码跑的；系统的主要工作是验收和拦截。

2. **「怎么证明没有编数据？」**
   三层：数字只来自实验 JSON；写作/评审共用同一事实基础；文内裁决表与结论交叉校验。
   边界是「不超出素材」，不是「语义绝对真实」。

3. **「评审 Agent 凭什么可信？」**
   它不给分，只给可核对的定位（`quote` 必须逐字出现）和可执行改法；
   编造的定位句会被确定性护栏清掉（`dropped_unverifiable_quotes`）。
   最终仍由人决定，不替代导师。

4. **「范文是不是拿来训练了？」**
   没有训练。只做确定性特征抽取，把「好论文的可观测特征」做成参照标尺注入提示词。

5. **「为什么之前那两篇读不通？」**
   那两次 `llm_written=false`，模型没参与写作，出的是模板骨架；
   闸门其实已判不可交付，只是界面没提示。现在补了红色横幅、主题校验和文本体检。

6. **「工作量/创新点在哪？」**
   不在单点模型，在闭环：事实同源、双轨评审、选材记忆、失败即拒交。
   每一条都有落盘证据和回归测试。

## 6. 明天不要说的话（边界）

- 不说「已经能自动产出可交付论文」——目前还没有一份 `llm_written=true` 的真实成稿。
- 不说「用清北论文训练了模型」——只是参照系，不是训练。
- 不说「专家评审已验证有效」——链路、降级、回流都通了，但真实模型输出还没样本。
- 不说「FACT_PACK / 00_run.json 已在主链路生效」——模块已并入，尚未接线。
- 不把组员的 13 个 lint FAIL 说成他的失误——那是模板骨架稿的必然结果，正好证明体检有用。
